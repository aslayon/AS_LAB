# 프로젝트 작업 지침

## 작업 범위와 환경

- 이 프로젝트는 WSL2 + VS Code에서 개발하는 FastAPI·SQLite·HTML/CSS/JavaScript 캐릭터 채팅 게임이다.
- 사용자 지시와 실제 코드를 우선한다. 현재 구현을 확인하지 않은 채 계획을 구현된 기능으로 설명하지 않는다.
- 시스템 Python은 변경하지 않고 프로젝트 전용 `.venv`를 사용한다. Python 3.14 의존성 문제가 확인되면 별도 런타임을 쓰는 방법을 먼저 설명한다.
- 유료 API 연결이나 시스템 전체 설정 변경은 사전에 설명한다. 원격 업로드는 사용자가 별도로 요청하기 전에는 하지 않는다.
- 기본 생성기는 `MockProvider`이며 mock 모드의 모델명은 없다. `CHARACTER_CHAT_PROVIDER=ollama`로 실제 `OllamaProvider`를 선택할 수 있다. 현재 Ollama 기본·검증 모델은 `exaone3.5:7.8b-instruct-q4_K_M`다. 기존 Qwen은 OLLAMA_MODEL로 선택 가능하며 가중치·실험 기록을 보존한다. 연결·GPU 상태는 코드와 실제 실행 결과로 확인하며 health의 설정 모델명을 실제 추론 성공으로 간주하지 않는다.
- 대화 반복·품질 문제는 실제 입력과 호출 내용을 재현하고 프롬프트·대화 전달·모델 설정을 비교하여 원인을 먼저 조사한다. 금지 지시, 문자열 유사도 차단, 강제 재생성 등 제약 추가는 최후의 수단으로 취급하며, 검증된 원인 해결 대신 사용하지 않는다. 정상적인 반복 답변을 오류로 만들지 않는다. 게임 규칙·JSON 형식·상태 변경·원자적 저장 검증은 유지한다. 확인된 원인과 아직 확인하지 못한 가설을 구분해 기록한다.

## 구조 문서와 스냅샷 관리

- `docs/architecture.md`는 실제 코드와 일치하는 최신 구조 문서로 유지한다. 관련 코드가 바뀌면 같은 작업에서 문서도 갱신한다.
- 전체 구조, 한 번의 메시지 처리, 체크포인트 저장·복원을 Mermaid로 설명하고 실제 파일명·주요 함수명을 연결한다. 각 그림 아래 쉬운 설명을 붙인다.
- 현재 구현과 향후 계획을 명확하게 분리한다. 코드에서 확인하지 못한 동작·모델·검증 결과를 추측하지 않는다.
- 최초 모의 응답 구조는 `docs/architecture-history/001-mock.md`로 보존한다.
- 응답 생성기 교체, DB 스키마·저장 구조 변경, 기억·요약·컨텍스트 조립 방식 변경, 분기·복원·상태 판정 흐름 변경 등 주요 구조 변경 **전**에 최신 구조 문서가 실제 코드와 맞고 현재 단계의 스냅샷으로 보존됐는지 확인한다.
- 변경 전 구조가 아직 보존되지 않았다면 먼저 스냅샷을 추가하고 기록한다. 이미 보존되어 있다면 불필요하게 같은 스냅샷을 복제하지 않는다. 설명 차이만 있으면 `docs/changes.md`에 그 차이와 구조상 동등함을 기록한다.
- 주요 구조 변경 완료 후 최신 문서를 갱신·검증하고 다음 번호와 단계명을 붙여 새 스냅샷을 추가한다. 파일명 형식은 `NNN-stage-name.md`이며, 예를 들어 첫 Ollama 연결 완료 단계는 그 시점의 다음 번호로 `NNN-ollama.md`를 사용할 수 있다. 번호는 기존 파일의 최대 번호 다음으로 정한다.
- 기존 스냅샷은 덮어쓰거나 삭제하지 않는다. 과거 문서의 오류를 발견하면 `docs/changes.md`에 정정 내용을 적고 필요하면 새 번호로 정정 스냅샷을 추가한다.
- 스냅샷은 문서 본문·다이어그램·확인 범위·남은 문제를 보존한다. 깊이가 다른 디렉터리에 복사할 때 상대 링크만 새 위치에 맞게 조정하고, 보존 시점과 단계를 표시한다.
- 다이어그램의 구성요소 이름·노드 ID·참여자 순서·흐름 방향·배치는 가능한 한 유지한다. 구성요소가 바뀌면 필요한 부분만 수정하고 변경 이유를 기록한다. Mermaid 자동 배치에 따른 픽셀 단위 동일 배치는 보장하지 않는다.
- 문서만 바뀐 경우 구조 스냅샷을 무조건 늘리지 않는다. 구조 설명의 의미가 달라졌거나 주요 단계가 완료된 경우에 새 스냅샷을 남긴다.
- Mermaid 렌더링 확장이 필요하면 설치 전에 알린다. 사용자 환경의 렌더링을 확인하지 못했으면 그 한계를 기록한다.

## 변경 기록

- 주요 작업마다 `docs/changes.md`에 날짜(Asia/Seoul), 단계, 변경 유형, 변경 이유, 이전과 달라진 점, 검증 결과, 남은 문제, 관련 스냅샷 링크를 기록한다.
- 변경 유형은 `문서·관리 변경 / 게임 동작 변경 없음`, `코드 동작 변경`, 또는 둘 다임을 명시한다. 코드 리팩터링으로 동작이 유지되면 그 사실을 구분해서 기록한다.
- 코드 변경이 없으면 기존 테스트 통과 결과를 이번 재실행 결과처럼 쓰지 않는다. 문서 링크·함수명·스냅샷 일치 확인과 게임 동작 테스트를 구분한다.
- 코드 동작이 바뀌면 해당 경로에 필요한 검증을 수행한다. 응답 생성기·기억·복원을 변경할 때는 잘못된 제안의 상태 미반영, 설정 보호, 체크포인트 이후 정보가 컨텍스트에 섞이지 않는지를 확인한다.

## 로컬 Git 관리

- 작업 전 저장소 루트·상태·기존 이력을 확인한다. 기존 저장소가 있으면 재초기화하거나 이력을 지우지 않는다. 사용자의 미커밋 변경을 덮어쓰거나 무관한 변경을 포함하지 않는다.
- 주요 단계마다 관련 코드·테스트·최신 구조 문서·해당 스냅샷·변경 기록을 함께 로컬 커밋한다. 문서만 바뀐 단계는 문서·관리 변경임을 커밋 메시지에 표시한다.
- 모든 커밋에 나중에 작업 흐름을 이해할 수 있는 짧은 한국어 설명을 남긴다. 제목은 `기능: ...`, `수정: ...`, `문서: ...`, `정리: ...`처럼 변경 유형과 구체적인 결과를 한 줄로 적는다. `백업`, `업데이트`처럼 내용이 드러나지 않는 제목만 쓰지 않는다.
- 커밋 본문에는 무엇을 바꿨는지와 이유, 실제 수행한 검증 결과를 간단히 기록한다. 남은 문제가 있으면 한 줄로 덧붙인다. 문서만 변경했으면 `게임 동작 변경 없음, 테스트 재실행 안 함`을 명시한다. 긴 설명은 `docs/changes.md`에 두고 관련 단계·스냅샷을 연결한다.
- 커밋 완료 후 사용자에게 짧은 해시와 한국어 변경 요약을 알려 준다. `git log --oneline`에서는 단계별 요약을, `git log -5`에서는 이유·검증까지 확인할 수 있게 한다. 이 규칙 적용을 위해 기존 커밋 메시지나 해시를 다시 쓰지 않는다.
- 커밋 전 staged 파일과 diff를 점검한다. 비밀정보, `.env`의 실제 값, 개인 키·인증 파일, `.venv`, 캐시, 실행 중 생성한 SQLite DB 및 WAL/SHM·저널 파일은 커밋하지 않는다. 새로 발견한 실행 산출물·비밀 파일 경로는 `.gitignore`에 추가한다.
- 비밀 파일은 내용을 출력하지 않고 경로와 포함 여부만 확인한다. 이미 추적 중인 비밀정보를 발견하면 커밋을 멈추고 노출 없이 문제를 설명한다.
- Git 작성자 설정이 없으면 사용자 신원을 추측하지 않는다. 사용자 지시에 다른 요구가 없으면 해당 커밋에만 `Codex <codex@localhost>`를 명시적으로 사용하고 알린다. 전역 Git 설정은 변경하지 않는다.
- 원격 저장소 생성·등록·push·업로드는 별도 요청 전에는 수행하지 않는다. 과거 커밋 수정이나 강제 push도 임의로 하지 않는다.

## 공개 기록 단계 이후의 기준

- archive-2.0은 공개 기록 목록 → ID 선택 → 공개 열람의 선택식 성공 경로를 제공한다. 신분증 검증·허가 발급은 미구현이다. 007 당시의 자유문장 해석 보류는 009의 명시적인 사용자 지시로 해제됐으며, 아래 자유 입력 기준을 따른다.
- 고정 기록과 진행 상태는 설정·스냅샷에 보존한다. archive-1.0 분기·체크포인트는 자동 마이그레이션하지 않고 기존 이력을 유지한다.
- 중요한 성공·거절·종료·다음 진행과 원문은 서버 확정 결과로 표시한다. 모델 대사를 사건 완료의 근거로 사용하지 않는다.
- 모델은 판정 후 예상 상태를 받지만 저장은 생성·독립 검증 성공 후 원자적으로 한다. 모델용 이력에는 저장된 모델 대사를 그대로 사실로 재사용하지 않고 턴의 서버 확정 결과를 사용한다. 원본 대사는 화면·복원을 위해 보존한다.
- CHARACTER_CHAT_DEV는 기본 false. 요청별 진단은 API/개발 패널에서만 노출하고 스냅샷·기억에 넣지 않는다. 원본 출력 및 실패 시 무저장 여부를 확인할 수 있게 유지한다.
- 자동 상태 검증과 실제 대사 품질의 수동 검토를 별도로 보고한다. 스키마가 유효한 거짓 대사도 존재할 수 있음을 부정 테스트로 보존하고, 이를 의미 검증 통과로 부르지 않는다. 최초 신분증·허가·목록 실패 사례는 tests/fixtures/identity-permit-loop.json과 docs/failure-cases/identity-permit-loop.md에 보존한다.

- 008 이후 모델용 이력은 confirmed_history()로 사용자 발언과 server 사건을 분리한다. 발언 접수 문구를 NPC 답변 예시로 넣거나 첫 인사를 매번 재주입하지 않는다. reading_context()는 현재 스냅샷의 실제 record_read 사건 순서에서 최근 본문을 구하며, 선택 상태·고유 ID 목록만으로 최근 열람을 추정하지 않는다.
- 회상 품질 변경은 동일 질문을 선택 전후·열람 후·열람 전 회귀에서 각각 확인한다. 허위 읽음 주장, 다시 읽기, 다른 기록 선택 뒤 최근 열람도 구분한다. 상태 무변화·본문 미전달 테스트와 실제 모델 질문 응답 품질은 별도로 검증한다.

## 자유 입력 단계 이후의 기준 (009)

- 최종 방향은 자유 대화·행동 시도다. UI 기본은 free, 선택식 direct는 개발·비교용으로 유지한다. API mode 생략은 기존 클라이언트 호환 때문에 direct다.
- 모델의 의도 제안은 kind/action/target/evidence만 허용한다. 서버가 근거와 대상을 확인해 기존 resolve()에 연결하며 성공·수치·사건 판정은 모델에 위임하지 않는다. 최소 지원 행동 밖이거나 모호하면 실행하지 않는다.
- 일반 대화·질문·가정·인용·부정·과거 주장을 실제 행동으로 확정하지 않는다. 일반 대화는 매번 열람 절차를 안내하는 작업으로 구성하지 않는다. 유한한 문법 보호와 모델 모두 오판 가능함을 명시한다.
- 서버 카드가 정확하다는 이유로 모순된 대사를 통과로 기록하지 않는다. 대사 생성 후 provider.review()를 실행한다. 형식·연결 오류는 턴 전체 무저장, 모순 판정은 초안 미저장 후 서버 근거 대체문으로 처리한다.
- 검토 모델이 오류를 놓친 실제 사례가 있으므로 종료·모호한 요청 되묻기·봉인 관련 인용/부정 확인의 최종 응답은 서버가 확정한다. consistency.status/reason과 debug.finalization_reason으로 모델 통과와 서버 마무리를 구분한다. 서버 대체를 모델 대사 품질 통과로 보고하지 않는다.
- 새로운 conversational_history()는 검토되거나 서버가 마무리한 발언 답변만 잡담 맥락으로 사용하며 사실 근거로 승격하지 않는다. 회귀 후 의도·대사·검토의 모든 입력에 미래 자료가 없는지 확인한다.
- 같은 행동의 direct/free 서버 결과 비교, 일반 대화·모호함·가정·인용·미지원 요청의 무변화, 오류 원자성, 실제 모델 대사 품질을 각각 검증·기록한다. mock 의도/검토는 고정 대역이므로 일반 자연어 이해로 설명하지 않는다.

## 장면·지식 분리 단계 이후의 기준 (010)

- 새 게임 설정은 archive-3.0이다. 비는 환경이며 보관소는 문서·장부를 보관한다. archive-2.0의 빗물/등불/정원 기록은 임시 검증 데이터였고 기존 분기에는 그대로 보존한다.
- 작가용 설정·플레이어만 아는 목적은 docs/scenario.md에 분리한다. 이 문서를 모델 입력으로 읽거나 CONFIG의 NPC 지식에 복사하지 않는다. 미확인 비밀·중요 기록의 실존을 확정하지 않는다.

## 모델 비교 기준 (2026-10-21)

- 학습용 프로토타입은 한 턴 전체 30–60초도 허용하며 속도보다 대사 품질을 우선한다. 단일 초안 시간과 의도·대사·검토 전체 시간을 구분한다.

- 비교 후보 EXAONE 7.8B/Qwen3 14B는 다운로드 상태로 보존하지만 기본 선택은 바꾸지 않았다. EXAONE은 표현이 개선됐으나 현재 의도 단계에서 공개 기록 선택이 실패했고, Qwen14도 언어 혼입·미관찰 행동 창작이 있었다. 상세 결과는 docs/reports/model-selection.md를 따른다.
- 후보 다운로드 전 정확한 태그·양자화·용량·메모리 추정/불확실성을 설명한다. 현재 WSL RAM 한도는 장비 32GB와 다를 수 있으며 시스템 설정을 임의 변경하지 않는다.

## 외부 대사 실험의 확인 단계 (2026-10-21)

- 외부 후보 하나의 현재 가격·소규모 실험 비용을 먼저 설명하고 **사용자 확인 전 유료 호출을 하지 않는다**. 현재 제안은 docs/experiments/external-dialogue-plan.md이며 실행 승인으로 간주하지 않는다.
- 기존 설명·질문·연속 대화를 재사용해 먼저 대사만 비교한다. 한국어 자연스러움·질문 직접성·중요 사실의 임의 확정을 평가하고 가벼운 묘사/제안을 완료 사건과 구분한다.

## EXAONE 연결 단계 이후의 기준 (011, 2026-10-21)

## 기밀·관계 설정 단계 이후의 기준 (012, 2026-10-21)

- 새 게임은 archive-4.0, confidential-1이다. ‘계몽의 서’의 존재/서린의 지식 범위는 서버 DEFINITIONS에만 두고 구체 위치·본문·잠입 경로는 추가하지 않는다. 기존 “미확인 비밀” 원칙의 예외는 명시적으로 확정한 이 기록뿐이다. 플레이어 목적은 여전히 NPC 초기 사실이 아니다. 버전별 정의는 기존 분기에 영향을 주도록 덮어쓰지 않고 새 버전을 추가한다.
- 정확한 제목의 부정·인용도 이름 언급으로 감지하지만 접근·독서·내용 지식·범죄 증거로 승격하지 않는다. 실제 제목은 미등장 시 모든 모델 입력에서 제외한다. 인지 뒤에도 출처 질문과 공개 경계만 전달한다.
