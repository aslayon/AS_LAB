# 실패 사례 · 신분증·허가·목록 요청의 순환

기록일: 2026-10-21 (Asia/Seoul). **사용자가 제공한 과거 플레이 사례**이며 이번 재실행 결과가 아니다. 원문 14회 입력과 응답은 [JSON 원본](../../tests/fixtures/identity-permit-loop.json)에 보존한다. UI의 HTML 엔티티·회귀 버튼 라벨은 제외했고 문장·오타는 유지했다.

## 증상과 확인된 구현 원인

사용자는 발언하기로 장소·기록·열람을 묻고, 신분증을 주었다고 말한 뒤 허가·목록을 요청했다. NPC는 구현되지 않은 신분증 검증·허가 발급을 안내하고 “검증하였습니다”, “허가를 받으셨습니다”라고 했다. 이후 목록을 거절하고, 장소 안에 있어야 한다거나 물리적 방문이 불가능하다고 설정을 만들어냈다.

당시 `resolve(state, action)`는 선택된 action만 판정했고 모든 `speak`는 상태 불변이었다. 신분증·허가 상태·공개 기록·열람 성공 규칙은 없었으며, `request_access`는 무조건 거절했다. 모델 대사는 상태 검증 대상이 아닌 자유 문자열로 저장되고 다음 이력에 재사용됐다. 이것이 대사의 완료 주장과 서버 상태가 다르게 유지되는 구현상의 원인이다. 모델 가중치 내부의 생성 원인을 알아냈다는 주장은 아니다.

## 007의 대응과 검증 한계

공개 기록 3개와 목록→선택→열람 규칙을 구현했다. 봉인 기록 거절·경고·종료는 유지하고 신분증·허가 절차는 기능 범위에서 명시적으로 제외했다. 중요한 결과·다음 진행·원문은 모델과 별도의 서버 확정 카드로 저장·표시한다. 상태에 근거한 요약·기억을 유지하고, 모델용 과거 답변은 해당 턴의 서버 확정 결과로 바꾼다. 표시용 원본 대사는 변경하지 않는다.

원본 14개 사용자 입력의 **mock 재생**은 발언만으로 허가·열람·종료가 바뀌지 않는지 확인한다. 이것은 원본 모델의 대사 품질을 자동 판정하는 테스트가 아니다. 스키마가 맞는 거짓 대사를 주입하는 부정 테스트도 남겨 서버 결과·요약·상태·다음 문맥이 이를 완료 사실로 쓰지 않음을 확인한다. 해당 거짓 대사 자체를 자동으로 의미 분석해 거부하는 기능은 없다.

실제 모델에서는 신분 증명 질문→신분증 제시 주장→처리 결과 질문→봉인 허가 요구→공개 경로 전환을 새로 시험했다. 모든 원문 14회 대화를 실제 모델로 재생한 것은 아니다. 결과와 남은 대사 문제는 [007 실제 품질 보고](../reports/007-ollama-quality.md), 구조는 [최신 문서](../architecture.md)에 있다.
