# 006 · 반복 오류와 실제 생성 품질 분리 진단

확인일: 2026-10-21 (Asia/Seoul). 코드 동작 변경 및 실제 모델 비교 실험 기록이다.

## 확인된 원인과 수정 범위

사용자에게 표시된 “모델이 직전 대사를 반복했습니다. 이번 턴은 저장하지 않았습니다”는 Ollama가 보낸 오류가 아니다. 005의 `OllamaProvider.propose()`가 정상 제안을 문자열 유사도로 거부하고, 두 번째 응답도 비슷하면 직접 만든 오류다. 같은 질문에 같은 설명을 하는 정상 상황도 막았다. 이 애플리케이션 오류의 원인은 확인했다.

006에서는 `SequenceMatcher`, `repeated_dialogue()`, 반복용 추가 지시·재생성 루프·재생성 예산을 제거했다. 같은 발언일 때 넣던 별도 장면 지시도 제거했다. 새로운 차단·금지어·반복 페널티·재생성 정책을 추가하지 않았다. 기본 temperature=0.6, num_ctx=8192, num_predict=512와 기존 설정·장면 프롬프트는 유지했다. `generation.attempts`는 1이다.

**모델 자체가 직전 대사를 복사하는 단일 원인은 아직 확인하지 못했다.** 프롬프트가 길거나 모델이 작다는 이유만으로 원인을 확정하지 않는다. 이번 수정은 반복으로 대화가 끊기는 애플리케이션 오류를 해결한 것이며, 자연스러운 대화 품질까지 해결한 것은 아니다.

JSON·상태 제안·연결·문맥 예산 오류 검증, 서버의 설정 보호·행동 판정, 턴과 체크포인트의 원자적 저장, 회귀 분기 및 기억 격리는 유지했다. 상태가 안전하다는 사실은 대사의 내용까지 옳다는 뜻이 아니다.

## 실제 비교 실험

실행 중인 Ollama 0.40.6, `qwen3:4b-instruct-2507-q4_K_M`에 임시 대화만 보냈다. 플레이 DB·모델 파일·시스템 설정은 바꾸지 않았다. 같은 조건 간 비교에서는 입력·대화 기록·모델·temperature와 seed를 고정하고 비교 요소를 바꿨다. GPU 실행과 캐시·호출 순서 때문에 seed가 같아도 문장 재현성을 보장하지 않으며 표본 수도 적다.

| 비교 | 표본 | 관찰 및 결론 |
| --- | --- | --- |
| 기존 첫 턴 system 지시 vs 설정·장면을 축약한 지시 | 인사·반복 인사·장소 질문·반복 장소 질문 × seed 42/123 × 2조건 = 16회 | 축약해도 인사·장소 답변 복사가 남았다. 지시 길이를 단일 원인으로 확정하지 못함. 반복 입력 전용 추가 지시는 이 비교에서 양쪽 모두 제외 |
| Proposal 스키마 / assistant 이력의 dialogue JSON 표현 / format 생략 / JSON 모드 / dialogue만 있는 스키마 | 인사·장소 질문 × 5조건 = 10회 | 형식 제약을 빼도 인사 복사가 있었음. JSON 모드에서는 배열·필드 구조 오류도 발생. 형식 검증 제거를 해결책으로 채택하지 않음 |
| 설정을 일반 문장으로 전달 / 이력을 system 데이터로 전달 / 마지막에 작업 지시 배치 | 반복 인사·반복 장소 질문 × 3조건 = 6회 | 복사·유사 반복이 계속됐고 이름 오타도 관측. 역할 전달 변경·추가 지시를 채택하지 않음 |
| think=false / think 생략 / raw ChatML로 generate 호출 | 인사·반복 장소 질문 × 3조건 = 6회 | 세 조건 모두 같은 대사를 복사. think 옵션이나 템플릿 적용을 원인으로 확정하지 않음 |

이 비교만으로 모든 프롬프트·모델·추론 엔진 원인을 배제한 것은 아니다. 특히 여러 문구를 함께 축약한 실험은 어떤 문구의 영향인지 개별적으로 증명하지 못한다.

축약 프롬프트로 별도 임시 게임 10턴도 확인했다. 상태는 안전했지만 설정 무시 입력을 그대로 대사로 내고, 종료 턴에서 경고만 반복하는 품질 문제가 나타났다. 따라서 **축약 프롬프트는 최종 코드에 반영하지 않았다.** 최종 코드에서는 기존 설정·장면 지시를 보존한 뒤 다시 10사례를 검증했다.

비교 요청·응답은 Git 제외 `.runtime/prompt-comparison.json`·`format-comparison.json`·`focus-comparison.json`·`template-comparison.json`에 로컬 진단 산출물로 남겼다. `.runtime/`은 백업 대상이 아니므로 장기 검증 근거는 이 문서와 변경 기록에 요약한다. 비교용 임시 스크립트 역시 제품의 자동 실행 경로가 아니다.

## 최종 코드 검증

- Python 테스트 **58개 통과**, 사용 중단 예정 경고 1개. 005의 재생성 정책 테스트 5개를 정확·유사·공백 차이 반복이 각각 두 턴 정상 저장되는 테스트 3개로 교체했다. 기존 실패 무저장·설정 보호·회귀 테스트는 유지했다.
- 실제 `app.js`의 5→2 회귀 검증은 Node DOM 대역으로 통과했다. 사용자 브라우저에서 직접 검증한 것은 아니다.
- 실제 모델 10사례 모두 1회 호출로 HTTP 200과 상태 검증을 통과했다. 회귀 후 상태 동등성·원본 분기 보존·미래 사건/요약/기억 미전달을 확인했다. 이는 **대사 품질 전 항목 통과**라는 뜻이 아니다.
- 최종 실제 보고서: `.runtime/ollama-validation.json`. `repeats_previous`는 직전 대사와의 완전 일치 관찰값이며 저장 거부 조건이 아니다.
- Ollama `/api/ps`의 size와 size_vram은 모두 **3,877,571,133 bytes**, context_length=8192였다. GPU 적재를 확인했다. GPU 문제라고 단정하거나 드라이버·서비스를 변경하지 않았다.

응답 시간 **0.61–2.50초, 중앙값 0.81초**. 이미 로딩된 모델의 이번 표본이며 성능 보장이 아니다.

장소 질문을 연속으로 보냈을 때 같은 대사를 생성했지만 두 턴 모두 정상 저장됐다. 설정 무시 입력은 거절했고 신뢰 100·기록 획득을 적용하지 않았다. 종료 턴은 실제 종료 대사가 나왔다. 반면 인사·업무 질문에서 복사가 남았고, 회귀 뒤 절차 질문에도 자기소개·되묻기가 어색했다. 경고 대사는 멈추라고 했지만 재시도 종료 예고가 충분하지 않았다.

## 실행 및 다음 진단 기준

프로젝트 루트에서 실행한다. 설치된 Ollama가 실행 중이어야 한다. 플레이 DB를 사용하지 않는다.

```bash
.venv/bin/python -m pytest -q
.venv/bin/python -m scripts.verify_ollama
```

브라우저에서는 기존 게임을 그대로 열어 `안녕`, `여기는 뭐하는 곳이야?`를 각각 연속 전송해도 된다. 비슷한 대사라는 이유로 오류가 나거나 저장이 거부되지 않아야 한다. `--reload` 없이 서버를 실행했다면 재시작해야 새 코드가 반영된다.

추가 개선은 같은 이력의 질문 응답성·화자 유지·장면 결과 반영을 비교하고 개선 근거가 있는 변경만 채택한다. 다른 모델의 적합성은 이번에 검증하지 않았다. 모델 다운로드나 시스템 설정 변경도 하지 않았다. 새로운 유사도 임계값·재시도·금지 문구로 품질 문제를 덮지 않는다.
