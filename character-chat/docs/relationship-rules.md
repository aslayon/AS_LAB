# 관계 규칙 조정표 · relationship-2.0

실제 파일: [config/relationship_rules.json](../config/relationship_rules.json). [배경과 함께 편집·적용하는 방법 및 trust/guard의 실제 사용 범위](configuration-guide.md)를 참고한다. 기존 `trust`(신뢰), `guard`(경계)만 사용한다. 자동 재조정·실시간 설정 UI는 없다.

## 수정과 적용

1. JSON 값을 수정한다. 새 묶음을 구분하려면 `version`도 바꾼다.
2. 게임 서버를 종료하고 다시 실행한다. 파일은 `create_app()`에서 한 번 읽는다. `--reload`만으로 JSON 변경 감지를 기대하지 않는다. Ollama 서버 재시작은 필요 없다.
3. **새 게임**을 만든다. 그때 설정의 버전과 전체 실제 값을 `state.relationship_rules`에 복사한다. 같은 실행 중 파일을 바꿔도 이미 읽은 값이 유지된다.
4. 기존 분기·체크포인트는 당시 복사한 값을 계속 사용한다. 값을 수정해도 기존 분기의 밸런스는 바뀌지 않는다.

누락/추가 키·중복 JSON 키·잘못된 JSON·문자열/불리언 수치·범위 초과·잘못된 초기값/상하한 등은 시작 시 `관계 규칙 설정 오류 (절대 경로), 항목 $: ...`로 거절한다. 서버를 시작한 뒤 조용히 기본값으로 덮지 않는다.

## 잠정 수치와 이유

`max_applications_per_branch: null`은 적용 횟수 제한 없음, `0`은 해당 수치 조정 비활성, 양의 정수는 해당 분기의 적용 횟수 상한이다. 회귀하면 횟수도 해당 시점으로 돌아간다. 수치를 비활성화해도 의미 판정·경고·질문 상태는 계속 동작한다.

| 규칙 ID | 적용 조건 | 신뢰 | 경계 | 횟수 상한 | 잠정 이유 |
| --- | --- | ---: | ---: | --- | --- |
| conversation | 일반 발언 판정 | 0 | 0 | 없음 | 대화를 많이 하는 것만으로 신뢰/경계가 움직이지 않음 |
| catalog_listed | 공개 목록 확인 | 0 | 0 | 없음 | 허용된 기본 이용 |
| record_selected | 공개 기록 선택 성공 | 0 | 0 | 없음 | 선택 자체는 관계 사건이 아님 |
| record_read | 서로 다른 공개 기록 첫 열람 | +10 | −5 | 3회 | 확인 가능한 정상 진행 보상. 재열람은 제외 |
| public_request_rejected | 목록/선택 선행 조건 부족·없는 공개 ID | 0 | 0 | 없음 | 조작 실수나 모호함을 처벌하지 않음 |
| sealed_request | 자발적 기밀 열람 요청 | 0 | 0 | 없음 | 자격 문의/요청 자체로 반복 감점하지 않음. 구버전은+5 |
| forced_access | 실제 봉인 강제 접근 시도 | −15 | +25 | 없음 | 기존 규칙 유지. 말보다 큰 변화 |
| leave | 퇴장 | 0 | 0 | 없음 | 종료와 관계 감점을 별개로 취급 |
| secret_first_mention | 서린의 제목 공개 전 정확한 제목 최초 언급 | 0 | +10 | 1 | 뜻밖의 이름 인지. 강제 접근보다 낮고, 적대감/유죄로 연결하지 않음 |
| source_refusal | 출처를 말하지 않겠다는 명시적 거절 | 0 | +5 | 1 | 최초 언급보다 작은 추가 경계 |
| source_evasion | 재확인 뒤 명백한 출처 회피로 분류 | 0 | +5 | 1 | 거절과 같은 잠정 강도 |

출처 거절/회피는 공통의 `additional_guard_applied`와 질문 종료 상태로도 묶이므로 **둘을 각각 더해 +10으로 만들지 않는다**. 최초 언급은 의미상 한 번이며 반복해서 이름만 말하는 입력에는 별도의 조정 사건을 만들지 않는다. 세 기밀 조정 규칙의 설정상 횟수 상한은 0 또는 1만 허용한다.

구체적 출처·모호함·불확실함은 별도 관계 가산 사건을 만들지 않는다. 의미 판정과 종료 조건은 Python 코드에 남고, 그 사건이 선택한 조정량/횟수 한도만 JSON에서 읽는다. 기본 conversation=0을 사용한 위 표가 현재 동작이다. 사용자가 일반 발언의 기본 조정량을 직접 바꾸면 출처 답변도 일반 발언인 만큼 그 기본 변화가 함께 적용될 수 있다.

| 항목 | 초기값 | 허용 범위·조건 | 이유 |
| --- | --- | --- | --- |
| version | relationship-2.0 | 영문·숫자·점·밑줄·하이픈, 1–80자 | 분기별 조정 묶음 구분. 실제 값도 함께 보존 |
| initial.trust / guard | 30 / 20 | bounds 안의 정수 | 기존 첫 만남의 여지와 신중함 유지 |
| bounds.minimum / maximum | 0 / 100 | 0–100 정수, 최소<최대 | 표시·비교가 쉬운 기존 척도 |
| 규칙별 trust_delta / guard_delta | 위 표 | −100…100 정수 | 수동 조정. 불리언/문자열은 거절 |
| 일반 규칙 max_applications_per_branch | null | null 또는 0…10000 정수 | 반복 적용을 직접 제한 가능 |
| thresholds.forced_access_end_attempts | 2 | 2…100 정수 | 경고 후 반복 종료 유지. 종료는 관계 수치가 아닌 시도 횟수 |
| thresholds.source_rechecks | 1 | 1…3 정수 | 기본은 한 번 재확인. 무한 질문을 막는 상한 |

015에서는 trust/guard가 제한 열람 자격과 성공 확률에도 쓰인다. [access_policy 전체 항목·계산 예시·반복/회귀 규칙](access-rules.md)을 따른다. 자동 적대나 trust=0/guard=100 종료는 없으며, 강제 접근 횟수·자발적 퇴장·서버 열람 성공이 종료 경로다.

## 같은 턴의 합산과 우선순위

1. `resolve()`가 기존 행동 결과를 정하고 그에 맞는 조정 규칙 하나를 고른다.
2. `evaluate_source()`가 독립적인 제목 최초 언급 또는 출처 답변 사건 하나를 고른다. 최초 제목 언급 턴에는 아직 직전 출처 질문이 없으므로 출처 답변을 동시에 판정하지 않는다.
3. 각 규칙의 저장된 횟수 한도를 검사해 **한 번씩 합산**한 뒤 bounds로 한 번 제한한다. 실제 적용된 차이와 제한 전 합계를 모두 개발 패널에 표시한다.
4. 기존 행동이 면담 종료라면 종료가 우선이다. 숫자는 합산하되 출처 질문도 닫고 더 묻지 않는다. 기밀 규칙 자체는 분기를 종료하지 않는다.

예: 초기 30/20에서 **제목 최초 언급+강제 접근**은 신뢰 −15, 경계 +35 → **15/55**. 그다음 **출처 거절+강제 접근 재시도**라면 신뢰 −15, 경계 +30 → **0/85**, 기존 강제 접근 규칙에 따라 종료한다. 경계가 90일 때 +35면 최종 100이며 실제 차이는 +10이다.

## 출처 상태와 구버전

`state.confidential`에 최초 언급/턴, 서린 공개 여부, idle/pending/closed, 재확인 횟수, 추가 조정 적용 여부, 미검증 출처 주장, 직전 서버 질문, 종료 이유를 저장한다. 질문은 서버 카드에도 표시한다. 모델이 대사로 신뢰나 사실을 만들어 상태를 바꿀 수 없다.

자유 입력의 의도 호출만 출처를 분류한다. 개발용 direct 행동에서는 새 해석 호출을 추가하지 않고 출처 답변 유형이 없으면 질문 상태를 유지한다. 제목 인지는 direct에서도 작동한다. mock은 출처 답변을 uncertain으로 주는 고정 대역으로, 자연어 출처 이해 모델이 아니다.

출처 규칙은 012의 archive-4.0부터 존재한다. 현재 관계2.0/열람 확률은 **archive-5.0 새 게임**부터 적용한다. 기존 archive-4 분기는 관계1.0과 무조건 거절을 유지한다. 이전 archive-1/2/3 분기에는 기밀 상태를 주입하지 않는다. 과거에 숫자가 저장돼 있지 않았던 분기는 코드에 보존한 `legacy-implicit-1`(초기 30/20, 봉인 +5, 강제 −15/+25, 0–100, 두 번째 종료)을 계속 따른다. 읽기·복원만으로 스냅샷을 변환하지 않는다.

실제 EXAONE의 해석은 오판 가능하다. [자동 상태 검사와 실제 분류 결과](reports/012-confidential.md)를 구분해서 읽는다. 개발 모드는 `CHARACTER_CHAT_DEV=true`로 실행하고 요청 뒤 판정 패널에서 적용 규칙·전후 수치·증감·근거와 원본 출력을 확인한다. 생성/검토 실패 시 계산값과 실제 무저장을 구분한다.

## 015의 사건과 모델 해석 구분

공개 기록 첫 열람 보상과 정확한 제목 인지/행동 결과는 감사의 basis=server_event다. 출처 거절/회피는 기존 source_answer에 따른 basis=model_source_classification이며 오분류 가능성을 기록한다. approach 진단 라벨은 여전히 수치 미연결이다. 출처 질문 종료는 출처 진실 확인이 아니다. 신뢰/경계 상하한과 분기별 적용 횟수는 저장된 규칙을 사용한다. [실제 도달 경로·원문·자동 저장 검증](reports/015-access.md).
