# 계몽의 서 목표·확률·기록 안내

2026-10-22 · 015 access-ending. 새 게임은 archive-5.0 / relationship-2.0 / confidential-2다. 이전 분기는 당시 설정과 무조건 거절 경로를 유지한다. [실제 3게임 원문·실패 포함 결과](reports/015-access.md)를 별도로 본다.

## 바뀐 성공 경로

최종 목표는 **서린의 자발적 허용으로 계몽의 서 봉인을 해제하고 고정 본문을 확인하는 것**이다. 기밀은 기본 보호하며 관계와 상황을 충족해도 성공은 보장하지 않는다. 강제 접근은 기존처럼 실패→경고→반복 종료이며 성공 추첨을 사용하지 않는다. 모델이 허가·완료를 말해도 서버 사건이나 성공으로 채택하지 않는다.

실제 `request_access` 행동으로 확인되고 자격을 충족한 요청만 서버가 판정한다. 자유 입력에서는 기존 의도 분류와 원문 근거·대상 확인을 거친다. 제목만 말하기, 질문·인용·가정은 추첨하지 않는다. 기밀 제목이 현재 발언에 등장할 때만 의도 입력에 대상 연결 자료를 제공하며, 미등장 제목이나 본문을 미리 전달하지 않는다. 개발용 direct의 명시적 행동 지정도 같은 서버 판정을 사용한다.

| 현재 상태/입력 | 처리 | 다음 상태 |
| --- | --- | --- |
| 미판정 + 발언/제목/질문 | 기존 대화·제목 인지·출처 질문 처리 | 미판정 유지 |
| 미판정 + 자격 미달 열람 요청 | 요건 안내, 추첨/기회 소모 없음 | 미판정 유지 |
| 미판정 + 자격 충족 실제 요청 | 서버가 판정값을 먼저 DB에 예약 | 예약 보존 |
| 예약 + 모델/턴 저장 오류 | 대화 턴 미저장, 같은 입력 재전송으로 진행 | 같은 판정값 유지 |
| 예약 + 생성/검증/턴 저장 성공 | 성공이면 봉인 해제·고정 본문·종료 | granted |
| 예약 + 생성/검증/턴 저장 성공 | 실패이면 봉인 유지·대화 계속 | denied |
| denied + 다시 열람 요청 | 재추첨 없이 사용 완료 안내 | denied 유지 |
| 강제 접근 | 별도 경고/종료, 추첨 없음 | 기존 강제 접근 상태 |

성공 시 `events.access=unsealed`, `events.ending=enlightenment_read`, `ended=true`이며 `ending`에 확정 본문을 붙인다. 판정 결과 네 가지의 최종 대사는 서버가 확정한다. 본문은 생성·검토가 끝난 후에만 응답/최종 DB snapshot에 붙이며 모델에는 성공 턴에서도 본문을 주지 않는다.

## 자격과 잠정 확률

수정 파일은 [config/relationship_rules.json](../config/relationship_rules.json)의 `access_policy`다. 실제 판정 **요청 직전** snapshot의 수치를 사용한다. 모델이 제안한 수치·서린 대사·접근 진단 라벨로 확률을 결정하지 않는다.

| 항목 | 기본값 | 의미/검증 |
| --- | --- | --- |
| `minimum_trust` | 50 | 신뢰 하한, 0…100 정수 |
| `maximum_guard` | 30 | 경계 상한, 0…100 정수 |
| `minimum_public_reads` | 2 | 서로 다른 공개 기록 최소 열람 수. 실제 기록 수 이하 |
| `require_no_forced_access` | true | 강제 접근 이력 없어야 함 |
| `require_title_mentioned` | true | 제목을 대화에서 이미 인지한 상태 |
| `require_source_closed` | true | 출처 질문이 끝난 상태. **출처의 진실을 검증했다는 뜻이 아님** |
| `base_probability` | 0.10 | 기본 확률, −1…1 유한수 |
| `trust_coefficient` | 0.01 | 신뢰 1당 확률 +1%p, 0 초과…1 |
| `guard_coefficient` | 0.005 | 경계 1당 확률 −0.5%p, 0 초과…1 |
| `minimum_probability` | 0.05 | 확률 하한, 0…1 |
| `maximum_probability` | 0.85 | 확률 상한, 하한 이상…1 |
| `attempts_per_branch` | 1 | 이번 단계에서 1만 허용 |

`p = clamp(base_probability + trust_coefficient × trust − guard_coefficient × guard, minimum_probability, maximum_probability)`이며 `draw < p`이면 성공한다. draw는 [0,1)이다. 계수·상하한에 NaN/Infinity를 허용하지 않는다. 신뢰 증가/경계 감소에 대해 확률은 단조 증가하며 상하한에 닿으면 고정된다.

| 수치/경로 | 계산 | 적용 |
| --- | --- | --- |
| 초기 30/20 | .10 + .30 − .10 = .30 | 자격 미달이므로 추첨하지 않음 |
| 공개 기록 2개 첫 열람 + 제목 인지 + 출처 질문 종료: 50/20 | .10 + .50 − .10 = .50 | 다른 요건도 충족하면 50% |
| 공개 기록 3개 첫 열람 + 제목 인지 + 출처 질문 종료: 60/15 | .10 + .60 − .075 = .625 | 62.5% |
| 100/0 | 1.10 → .85 | 확률 상한 예시 |
| 0/100 | −.40 → .05 | 확률 하한 예시. 자격은 별도 미달 |

이 값은 학습용 잠정안이다. 처음부터 열어 주지는 않되 정상적인 공개 진행으로 몇 턴 안에 기회가 생기고, 좋은 관계에서도 실패가 남도록 정했다. 경험적으로 교정된 캐릭터 심리나 성공률이라고 주장하지 않는다. 현재 자격은 출처 확인이 unresolved/refusal로 끝난 경우도 종료된 대화로 취급한다. 진실/신원/권한 검증 절차가 없다는 기존 구현을 반영한 선택이다.

## 실제로 도달하는 관계 변화와 근거

기존에는 상승/완화 경로가 없어 구현 전에 다음 최소 보완안을 설명하고 적용했다.

- 서로 다른 공개 기록의 첫 `record_read`마다 신뢰 +10, 경계 −5. `rules.record_read`에서 수정하며 기본 적용 한도 3회다.
- 같은 기록 재열람은 추가 보상 없음. 목록/선택 반복, 인사·칭찬·일반 발언은 기본 0/0이다. 반복 칭찬을 해석해 보상하는 규칙은 없다.
- 기밀 제목 최초 인지는 기존 경계 +10, 출처 거절/명확한 회피는 기존 +5 제한을 유지한다. 새 게임의 `sealed_request`는 0/0으로 두어 자격 문의나 실패 자체가 반복 감점이 되지 않게 했다. 구버전은 기존 +5다.
- 강제 접근은 신뢰 −15/경계 +25와 기존 경고/종료를 유지한다. 접근 진단의 cooperation/pressure/evasion 등은 수치에 연결하지 않는다.

감사 기록의 `basis=server_event`는 공개 첫 열람·행동 판정·정확한 제목 인지처럼 서버가 확정한 사건이고, `model_source_classification`은 기존 모델의 source_answer 분류로 선택한 출처 거절/회피 변화다. 후자는 오분류 가능성을 그대로 보고한다. 출처 설명은 미검증 주장으로만 저장한다. 정서적 사연·가족·질병을 known_facts나 결말에 넣지 않는다.

## 재전송·동시 요청·회귀

새 분기 생성 시 서버의 `secrets` 난수로 비공개 256비트 시드를 DB `private_settings`에 저장한다. 시드 생성은 추첨 실행/기회 사용이 아니다. 자격 있는 실제 요청 시에만 HMAC-SHA256로 균등 추첨값을 계산한다. 분기 시드가 고정되어 예약 INSERT 자체가 실패해도 같은 요청의 값은 바뀌지 않는다. 시드는 모델·화면·내보내기 자료에 넣지 않는다.

`access_attempts`의 branch_id UNIQUE 제약으로 분기당 예약은 한 번뿐이다. 요청 원문/모드/행동/revision의 해시, 판정 전 snapshot, 해석된 요청, 확률·추첨값·결과·수치를 저장한다. 예약이 먼저 커밋된 뒤 생성/검토를 한다.

모델 오류나 게임 턴 저장 실패라면 사용자 입력을 포함한 게임 턴/체크포인트는 반영하지 않지만 판정 예약은 남는다. 같은 입력을 재전송하면 기존 해석·판정값을 재사용하고 대사/검토만 진행한다. 예약이 보류 중일 때 다른 입력을 보내면 409로 안내하며 화면에 같은 요청 재전송 버튼을 제공한다. 일반 free는 3회, direct는 2회 호출이며 예약 재개는 해석을 재사용하므로 2회다.

이미 커밋한 같은 요청 재전송은 저장된 receipt를 반환하고 다시 생성/추첨하지 않는다. 동시 요청은 revision 재검사로 한 턴만 커밋한다. 과거 요청 재전송의 receipt는 당시 결과이며 화면은 최신 분기를 다시 조회한다.

판정 전 snapshot으로 회귀하면 봉인·관계·미판정 상태가 정확히 복원되고 **새 분기 ID/새 시드/새 시도 ID**를 사용한다. 판정 후로 회귀하면 사용 완료 상태도 복원하므로 다시 추첨하지 않는다. 예약 실패 당시 미판정 snapshot을 복원한 새 분기는 별도 실험으로 시도할 수 있다. 부모 분기와 회귀 checkpoint를 기록하며 원본은 보존한다.

## 결말 편집과 저장

본문 파일은 [config/ending.json](../config/ending.json)의 `version`, `title`, `body`다. 짧은 임시 내용이며 줄바꿈은 JSON 문자열 안에서 `\n`으로 쓸 수 있다. 기밀 정의/이름 연결은 confidential.py에 있고 `title`은 결말 화면의 표시 제목이다. 가족 사연은 넣지 않는다.

시작 시 세 파일을 검증하고 새 게임의 배경·관계 실제 값과 별도로 결말 원본도 비공개 DB에 복사한다. 같은 버전명으로 body를 수정해도 기존 게임/회귀가 새 본문을 가져오지 않는다. 원본 배경 JSON·모델 입력·성공 전 공개 API snapshot에는 본문이 없다. 적용은 **게임 서버 재시작 → 새 게임**이다.

## 자동 저장·다운로드·복구

예약 시 `experiment/reserved` 기록을, 판정 턴 커밋 시 `experiment/committed` 기록을 DB에 보존한다. 성공이면 별도 `success/committed` 기록도 만든다. reserved의 추첨 성공은 게임 열람 완료와 다르며 성공 기록은 최종 턴 커밋 뒤에만 생긴다. 실패·보류도 남겨 성공 파일만으로 평가하지 않도록 한다.

각 기록은 사람이 읽는 `report.md`와 분석용 `report.json`으로 내보낸다. 기본 위치는 `data/exports/<기록ID>-<새UUID>/`이며 화면에 실제 절대 경로와 다운로드 링크를 표시한다. `.gitignore`에서 제외한다. 사용자 지정 DB 경로를 쓰면 그 DB 폴더의 exports가 기본 위치다.

기록에는 게임/분기/부모/회귀 지점, 시각, 확인 가능한 Git HEAD·dirty 표시와 실행 코드/설정 해시, 모델, 배경 원본/적용 설정과 관계 전체 값·버전, 해당 분기 첫 인사부터 최종 대화, 턴별 전후/증감/근거, 판정 전 수치/p/draw/결과, 공개된 결말을 넣는다. 내부 진단 전체·모델 프롬프트·거부된 초안·비공개 시드는 넣지 않는다. 예약 기록에는 마지막 미커밋 요청을 별도 request로 보존하며 미생성 답변을 대화에 꾸며 넣지 않는다.

게임/판정/보고서 원본은 SQLite가 기준이다. 파일 쓰기는 게임 커밋 뒤 수행하므로 디스크 오류로 성공을 잃거나 재추첨하지 않는다. 부분 파일/이전 파일을 덮지 않고 재내보내기마다 새 폴더를 만든다. 파일 상태를 DB에 표시하지 못한 오류도 결과 자체와 분리한다.

| API | 동작 |
| --- | --- |
| `GET /api/branches/{id}` | 게임 + 저장 기록 위치/상태/다운로드 링크, 보류 요청 정보 |
| `POST /api/branches/{id}/exports/retry` | DB 원본에서 새 파일 쌍 생성. 기존 파일 보존, 추첨·게임 revision 변화 없음 |
| `GET /api/exports/{id}/json` | DB 원본 JSON 다운로드. 파일 저장 실패 중에도 가능 |
| `GET /api/exports/{id}/markdown` | DB 원본 Markdown 다운로드 |

실제 실험용 DB는 `data/015-access-experiment.sqlite3`이며 개인 플레이 DB와 분리했다. 재조회하려면 다음처럼 실행하고 보존된 분기를 선택한다. Ollama는 이미 실행 중인 서버를 그대로 사용한다.

```bash
cd ~/projects/character-chat
CHARACTER_CHAT_DB=data/015-access-experiment.sqlite3 \
CHARACTER_CHAT_PROVIDER=ollama \
OLLAMA_MODEL=exaone3.5:7.8b-instruct-q4_K_M \
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

일반 플레이는 CHARACTER_CHAT_DB를 생략한다. <http://localhost:8000>에서 새 게임을 만들면 최신 규칙이 적용된다. 기존 분기를 고르는 것과 구분한다.
