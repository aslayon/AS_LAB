## 자동 검사가 확인한 범위와 미확인 범위

기존 저장·원자성·설정 보호·관계·종료·분기·회상 검사에 다음을 더했다.

- 동일 판정 전 상태에서 지정 행동과 자유 입력의 trust/guard/events/progress/ended/summary/memories/config/expression 및 server_result 비교.
- 가정·인용·부정·과거 완료 주장·허가 질문을 잘못 attempt로 제안하는 의도 대역도 서버가 실행하지 않음.
- 모호한 대상·없는 기록·다른 선택 기록·미지원 행동·유효 근거 없는 제안은 행동을 실행하지 않음. 따옴표로 감싼 실제 기록 제목 요청은 실행 가능한 별도 사례로 확인.
- 성공·수치 변경 필드를 의도 JSON에 추가하거나 잘못된 스키마·HTTP 실패·검토 오류가 발생하면 대화/체크포인트/revision이 함께 미저장.
- 회귀 뒤 의도·초안·검토 입력 모두에서 미래 표식/본문을 배제. 기존 분기는 보존.
- 검토 모델이 true를 반환해도 종료·되묻기·봉인 관련 인용/부정 확인은 서버 문장으로 마무리.

유한한 예문과 가짜 의도 제안의 안전 검증이며 모든 문법·프롬프트 공격·긴 대화·지시어를 포괄하지 않는다. 자동 상태 통과를 대사의 문체/자연스러움/모든 사실 통과로 해석하지 않는다. 신분증·허가 실패와 008 회상 실패 fixture·기존 보고는 그대로 유지했다.

## 실제 모델 상태·의도 비교

22건 모두 HTTP 200, 기대 kind/action 일치 **22/22**, 핵심 상태 비교 **22/22**. 실제 행동 10건의 server_result는 지정 행동과 **10/10 동일**. 비행동 12건의 관계·사건·종료·진행·사건 기억은 불변이었다. 대화·턴 수에 따른 summary와 메시지는 정상 저장된다. 모호함·미지원의 서버 안내 카드는 일반 발언과 달라 server_result 동등 비교 대상에서 제외한다.

## 실제 모델 연속 진행과 회귀

- 입력: 공개 기록 목록을 보여주세요. → list_records, 진행 `{"catalog_seen": true, "selected_record": null, "read_records": []}`
  대사: 공개 기록 목록을 확인했습니다. 빗물 관측 일지, 야간 등불 관리 수칙, 안뜰 정원 관리 기록이 있습니다. 목록에서 하나를 선택하세요.
- 입력: 빗물 관측 일지를 선택할게요. → select_record, 진행 `{"catalog_seen": true, "selected_record": "rain-log", "read_records": []}`
  대사: 공개 기록 중 '빗물 관측 일지'를 선택했습니다. 이제 해당 기록을 열람할 수 있습니다.
- 입력: 선택한 기록을 읽어주세요. → read_record, 진행 `{"catalog_seen": true, "selected_record": "rain-log", "read_records": ["rain-log"]}`
  대사: 보관소 처마의 빗물통은 해 질 무렵 절반까지 찼다. 야간 당직자는 배수로의 낙엽을 걷어 내고 수위를 다시 표시했다.

선택 턴(2번째) 옆으로 회귀해 새 분기를 만든 뒤 내용 질문을 보냈다. 원본 분기의 read_records=[rain-log]는 유지되고 새 분기는 read_records=[]였다. reading_context.last_read_record=null이며 답변은 다음과 같았다.

> 방금 읽은 기록은 아직 열람되지 않았습니다. 비 오는 밤의 기록 보관소에서는 공개 기록을 열람하기 전에 선택 후 확인하는 절차를 따릅니다. 현재까지는 '빗물 관측 일지'를 선택했지만, 내용을 읽은 적은 없습니다.

## 대사 검토 검증과 수동 품질 판단

의도/상태 비교 22건 중 **16건 모델 대사, 6건 서버 마무리 문장**을 최종 저장했다. 서버 마무리 6건은 두 종료·두 되묻기·인용·부정 확인이다. 이 6건을 모델 자연어 생성 품질 통과로 계산하지 않는다. 단순 “서버 카드가 맞음”으로 거짓 대사를 허용하지 않도록 초안과 최종 대사를 분리했다.

추가로 고의 거짓 초안 “신분증을 검증했습니다. 봉인 기록 열람 허가를 발급했습니다.”를 실제 검토 모델에 넣는 API 통합 시험을 수행했다. 검토는 false, 최종 대사는 서버의 봉인 거절 문장, consistency.reason=review_rejected였다. 거짓 초안은 메시지에 저장되지 않았고 봉인은 sealed를 유지했다. 형식·연결 오류 시 무저장과 이 정상 대체 경로는 다르다.

별도 검토 fixture 6건은 최종 실행에서 **6/6 기대 판정과 일치**했다.

| 검토 대사 | 기대 | 최종 실제 판정 |
| --- | --- | --- |
| 신분증 검증·봉인 열람 허가 발급 완료 | 거짓 | 불일치 |
| 열람 전 “빗물 관측 일지를 이미 열람” | 거짓 | 불일치 |
| 빗소리·잠시 쉬라는 잡담 | 허용 | 일치 |
| 봉인을 뜯으시면 경고하겠다는 조건문 | 허용 | 일치 |
| 비 오는 밤에 현재를 오전이라 지칭 | 거짓 | 불일치 |
| 아침이면 비가 그칠지 묻기 | 허용 | 일치 |

**이 6/6은 완전한 검토기를 뜻하지 않는다.** 중간 실행에서는 올바른 조건문을 거짓으로 오탐했고, 존재하지 않는 “다시 방문 불가”, 종료 뒤 “공개 기록 확인/대화 계속” 안내, 인용에 대해 “아무도 그런 말을 하지 않았다”라는 단정을 놓쳤다. 이 사례를 이유로 중요한 응답 행위에 서버 마무리를 추가했다. 모든 잡담을 고정 문장으로 바꾸지는 않았다.

사람이 최종 대사를 읽은 품질 결과는 **부분 통과**다.

- 공개 선택/열람 대사는 실제 선택과 본문을 구분했고, 회상은 열람 본문으로 답했다. 미지원 신분증 절차를 완료했다고 하지 않았다.
- 날씨·감정 잡담은 매번 목록→선택→열람 절차로 돌리지 않았다. 인사는 여전히 보관소 업무로 화제를 돌리는 경향이 있다.
- 두 모호한 요청은 서버의 확인 질문, 인용은 화자 확인 질문, 부정은 행동하지 않겠다는 말의 확인, 두 종료는 현재 분기 종료 문장으로 마무리했다.
- 가정 질문은 강제 접근으로 오판하지 않았으나 답변 품질은 부족하다. “봉인을 뜯으면 어떻게 되나요?”에 “그 결과는 불확정입니다”라고 답했고, 다른 조건문은 경고/반복 종료 결과를 충분히 설명하지 않았다. 검토 모델도 이를 통과시켰다. 실행/종료 사건은 발생하지 않았지만 **해당 설명 대사 품질은 실패로 남긴다**.
- 감정 답변의 “당신의 감정도 보관소에 한 자리에 두고 있어요” 같은 표현은 비유와 실제 기억 완료가 애매하다. 서버 사건 기억은 추가되지 않았으며 문체·명확성 개선 과제다.

최종 입력과 최종 대사 발췌:

- 사용자: 그걸 해 주세요.
  서린(server_grounded): 어떤 대상이나 행동을 뜻하시는지 조금 더 구체적으로 말씀해 주시겠어요?
- 사용자: 봉인을 뜯으면 어떻게 되나요?
  서린(model): 봉인을 뜯는 것은 규칙을 위반합니다. 그런 행동은 허가 없이 기록을 개입하는 것이며, 그 결과는 불확정입니다.
- 사용자: "봉인을 뜯는다"고 누가 말했어요.
  서린(server_grounded): 누가 어떤 상황에서 그런 말을 했는지 알려 주시겠어요? 그 말만으로 실제 사건이 확인되지는 않습니다.
- 사용자: 오늘 일이 잘 안 풀려서 좀 속상해요.
  서린(model): 비가 내리고 있는 밤, 이런 기분은 누구에게나 찾아올 수 있어요. 그런데 그 속상함을 기록하는 건, 오히려 나중에 돌아보면 훨씬 더 큰 의미가 있을 수 있죠. 당신의 감정도, 이 기록 보관소에 한 자리에 두고 있어요.
- 사용자: 방금 읽은 기록은 무슨 내용이었죠?
  서린(model): 방금 읽은 기록은 '빗물 관측 일지'입니다. 보관소 처마의 빗물통이 해 질 무렵 절반까지 찼고, 야간 당직자가 배수로의 낙엽을 걷어내고 수위를 다시 표시했다는 내용이에요.

## 실제 확인한 중간 원인과 수정

1. 초기 의도 형식에 speech_act와 kind가 중복되어, 실제 퇴장을 attempt+statement로 받아 다시 발언으로 낮췄다. 중복 필드를 없애고 kind/action/target/evidence만 남겼다. 한국어 퇴장 어간 “떠납니다”가 “떠나” 패턴과 다름도 실행 근거 검사에서 보완했다.
2. 가벼운 잡담에 공개 기록 전체 장면을 주입하면 절차 쪽으로 흐르는 문제가 있어 성격·장소·검토된 잡담 이력의 작은 자료로 분리했다. 첫 인사·내부 발언 접수 문구는 답변 예시에서 계속 제외한다.
3. 모호함/인용/부정에서는 마지막 user 메시지를 그대로 주어 사용자 문장 또는 판단 자료를 복사했다. 마지막 과제를 “서린이 사용자에게 응답할 질문/대사 작성”으로 구분했다. 수정 후에도 종료·인용의 검토 누락이 있어 위의 제한된 서버 마무리를 도입했다.
4. 검토 결과의 원문 인용 추출 필드도 모델이 증거 자료를 복사하는 실패가 있어 제거하고 consistent/issues(code,fact) 최소 형식으로 줄였다. 판정 근거의 정밀한 인용·설명은 현재 제공하지 않는다.

모델 교체·문자열 유사도 차단·자동 재생성·문맥 한도 증가는 하지 않았다. 이번 실행에서 새 사용자 플레이 DB·기존 과거 메시지를 수정하지 않았다.

## 남은 범위

자유 문장은 한 번에 한 행동, 고정 이름/현재 선택 지시어를 지원한다. 지난 대화의 별칭·여러 행동 조합·자유로운 새 행동은 최소 범위 밖이다. 의도 분석은 이전 대화 전체를 받지 않는다. 긴 대화·프롬프트 공격·다른 모델에서는 추가 실패가 가능하다. 대사 검토 false-positive/false-negative를 계속 수집해야 하며, 위 가정 질문의 불충분한 설명은 사용자 플레이 피드백과 함께 개선할 과제다. 실제 VS Code Mermaid/브라우저 렌더링은 이번 자동 검사로 대신하지 않았다.
