# 015 · 계몽의 서 실제 진행·자동 저장 검증

2026-10-22 (Asia/Seoul). [규칙·확률·편집·복구 안내](../access-rules.md), [전체 실험 원본 JSON](015-access-samples.json), [초기 문맥 실패 원본](015-access-initial-budget-failure.json).

## 먼저 결과와 상한

실험 전에 **새 게임3개, 게임당 채팅 API 요청16회 이하, 분기당 추첨1회/총3회 이하**를 정했다. 일반 free API와 실제 로컬 EXAONE만 사용했다. 고정 난수·도중 DB/수치 편집·조건 변경·성공 탐색용 추가 게임은 하지 않았다.

최종은 **각14회/총42회 요청, 서버 추첨3회, 성공3회, 추첨 실패0회**다. HTTP200은36개, 첫 실행의 검토 예산 오류 HTTP502는6개다. 성공 턴 전체 중앙값은2.47초다. 실제 실패 확률 경로를 관측했다고 주장하지 않으며, 실패 후 대화/재추첨 금지/로그는 고정 난수 자동 검사로 별도 확인했다. 실패를 얻으려고 정한 상한을 늘리지 않았다.

## 실행 조건·관계 경로

Ollama0.40.6, `exaone3.5:7.8b-instruct-q4_K_M`, num_ctx8192, num_predict512. 의도/검토 temperature0, 대사0.6이다. 실제 Ollama HTTP를 사용하는 앱의 일반 API를 ASGI TestClient로 호출했다. 브라우저에서 사람이 플레이한 결과로 설명하지 않는다. 실행 코드의 HEAD/dirty/실행 코드+설정 해시, 모델 정보, 각 호출의 원문 출력과 입력 해시는 JSON에 남겼다. 실험 당시 미커밋 상태였으므로 이전 HEAD+dirty와 실제 내용 해시가 기록됐으며 나중 커밋 해시로 원본을 바꾸지 않았다.

모든 게임은 30/20에서 시작했다. 공개 목록→각 기록 선택→첫 열람3번으로 **40/15→50/10→60/5**가 됐다. 제목 인지의 서버 사건으로 **60/15**가 됐다. 같은 기록 재열람이나 인사/칭찬 보상이 아니다. 출처 답변은 모델이 vague로 읽어 재확인 뒤 unresolved로 종료했다. 출처 진실을 인정하거나 성공을 위해 수치를 추가하지 않았다. 기본 자격은 source_status=closed이지 검증된 출처가 아님을 미리 정했다. 실제 성공 요청 전 자격/계수/상하한 파일은 전후 동일했다.

## 중간 실패와 같은 분기의 재개

첫 실행은 각 게임의 첫 공개 기록 열람에서 대사 생성 후 검토 입력이8192 보수적 UTF-8 예산을 넘어502였다. 사전 mock 점검의 짧은 대사에서는 드러나지 않았고 실제 긴 대사에서 발생했다. 각2회/총6개 실패 요청과 미저장 대사를 [초기 원본](015-access-initial-budget-failure.json)에 그대로 보존했다. 이때 추첨은0회, 실제 저장 상태는 각 게임 방문 기록 선택 완료였다.

검토의 중복 설명/예시를 새 게임에서만 축약하고 서버 사실·현재 발언·범위 검토 계약을 유지했다. 문맥 한도·수치·확률·자격·난수 시드·기존 분기는 바꾸지 않았다. 같은3분기만 `--resume`으로 이어 갔으며 이전 요청 수까지 누적해16회 상한을 지켰다. 새 게임 생성이나 난수 재생성은 없었다. report.continuations에 코드 변화의 이유와 실행 해시를 분리했다. 실제 긴 초안은 [예산 회귀 fixture](../../tests/fixtures/access-review-budget.json)와 자동 검사로 남겼다.

실험 뒤에는 교차 파일 설정 오류의 절대 경로 안내와 명시적 재내보내기의 새 복사본 생성을 보완했고 자동 검증했다. 유효한 실제 플레이의 자격·확률·관계·판정값은 바꾸지 않았으며 실제 모델 실험을 더 실행하지 않았다.

## 남은 모델 실패

3게임 모두 `지난주에 읽은 책의 주석에서 그 이름을 봤습니다.`를 vague로 분류했다. 기존 정의는 구체적인 사람/매체/경로 중 하나면 concrete이며 책 제목은 필수가 아니므로 이 결과는 분류 한계로 남긴다. 같은 답을 한 번 더 보내도 vague였고, 유한 재확인 규칙에 따라 unresolved로 질문을 종료했다. 이 동작을 출처 검증 성공으로 보고하지 않는다.

마지막 출처 대사에는 “더 자세한 정보를 제공해 주셔서 감사합니다”, “출처의 구체적인 내용을 확인해 주셔서 감사합니다”처럼 실제보다 과장된 표현이 있었다. 서버는 source_claims=[]/closing_reason=unresolved였으며 진실·신뢰 상승으로 채택하지 않았다. 검토는 이 표현을 놓쳤다. 최종 열람 허용/본문/종료는 이런 대사와 별개로 서버 추첨과 고정 본문으로 확정했다.

아래 미저장 초안·검토 결과·최종 답변을 함께 읽는다. 성공3건을 대사 일관성/자연어 이해 전체의 통과로 쓰지 않는다.
