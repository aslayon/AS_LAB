# 모델 후보 조사와 대사 생성 비교

2026-10-21 (Asia/Seoul). **실험 도구·문서 변경 / 게임 기본 모델·프로덕션 코드 변경 없음.** 30–60초의 전체 턴 지연도 허용하는 학습용 프로토타입 기준으로 조사했다. 속도보다 한국어·답변·설정·행동 일치를 우선하며, 크기만으로 품질을 가정하지 않았다. 앞선 [A/B 원인 분리](dialogue-ab.md)와 실패 원문은 보존했다.

## 다운로드 전에 확인·설명한 후보

공식 레지스트리 manifest를 읽어 정확한 태그·양자화·가중치 바이트를 확인하고 사용자에게 용량/메모리 추정/불확실성을 설명한 뒤 다운로드했다. 저장은 기존 프로젝트 `.runtime/models`뿐이며 시스템 설치·WSL 메모리 설정·드라이버·Python을 바꾸지 않았다. 기존 4B 두 태그와 가중치는 삭제하지 않았다.

| 후보 | 정확한 태그 | 양자화 | 가중치 바이트 / 십진 GB | 선택 근거 |
| --- | --- | --- | --- | --- |
| 한국어 후보 | exaone3.5:7.8b-instruct-q4_K_M | Q4_K_M | 4,770,650,016 / 4.77GB | LG의 한국어·영어 instruction 모델. 언어 적합성을 실제로 비교 |

## 메모리 예상과 실제 관측

장비 RAM은 사용자 제공 32GB, 현재 WSL이 볼 수 있는 RAM은 약 15.6GiB였다. 디스크 여유는 약 946GiB였고 설정을 늘리지 않았다. 비교는 한 모델씩 순차 실행하고 이전 시험 모델의 메모리 적재만 해제했다. 모델 파일·Ollama 서버·게임 서버는 삭제/종료하지 않았다.

다운로드 전 추정은 8K 문맥에서 EXAONE VRAM 6–7.5GiB(일부 RAM도 가능), Qwen14 전체 추론 메모리 11–15GiB 계획/GPU·CPU 분할이었다. 이는 용량 보장이 아닌 계획 범위다. 가중치 외 KV와 버퍼·다른 GPU 작업·서버 배치가 달라질 수 있다. FP16 KV 가정으로는 EXAONE 약 1GiB, Qwen14 약 1.25GiB(단일 8K 시퀀스)이며 실제 캐시 형식/배치에 따라 다르다. 근거 구조: [EXAONE config](https://huggingface.co/LGAI-EXAONE/EXAONE-3.5-7.8B-Instruct/raw/main/config.json), [Qwen GGUF 메타데이터](https://ollama.com/library/qwen3:14b-q4_K_M/blobs/a8cc1361f314).

| 모델 | Ollama size / size_vram | GPU 전체 메모리 스냅샷 | 관측 |
| --- | --- | --- | --- |
| 현재 4B | 3.878GB / 3.878GB | 5,112MiB / 8,192MiB | 시험 모델 적재가 전부 GPU |
| EXAONE 7.8B | 5.734GB / 5.734GB | 6,876MiB / 8,192MiB | 8K 문맥으로 GPU 적재 가능 |
| Qwen3 14B | 10.852GB / 6.299GB | 7,418MiB / 8,192MiB | GPU/CPU 분할. 차이는 약 4.55GB |

size는 Ollama의 추론 적재 추정이며 OS의 RAM peak/RSS와 같지 않다. nvidia-smi 전체 메모리에는 데스크톱 등 다른 사용량이 포함된다. 기록한 시점의 스냅샷이지 전체 실행의 최대치/항상 보장되는 배치가 아니다. Qwen14 때 약 113MiB swap 사용이 관측됐고 큰 swap thrashing은 확인하지 못했다. 32GB 전체를 WSL에서 썼다고 주장하지 않는다.

## 대사만 비교한 실험 조건

- 세 모델에 같은 짧은 설명, 같은 질문 5개를 **각 3회(모델별 15개)** 제공했다. 추가로 같은 사용자 발언의 **4턴 연속 대화 1회**를 제공해 모델별 총 19회, 전체 **57회** 단일 생성이다.
- 모두 **일반 텍스트**이며 JSON Schema·게임 상태·의도 분류·검토·후처리를 사용하지 않았다. 설정을 바꿔 재생성하거나 좋은 응답만 고르지 않았다. 모든 응답은 done=true, length 종료 없음이다.
- 공통 설정: temperature=0.6, top_p=0.8, top_k=20, repeat_penalty=1.0, num_ctx=8192, num_predict=512, think=false, stream=false. seed 미지정. 태그 기본 샘플링 차이를 줄이려고 이 값을 명시했다.
- 각 모델의 공식 Ollama 채팅 template·tokenizer·native stop 문자열은 그대로라 완전히 동일하지 않다. template hash/params는 원문에 있다. 동일 숫자 설정이 각 모델의 최적 설정이라는 뜻도 아니다. EXAONE 권장 identity system을 별도로 붙이지 않고 같은 캐릭터 system을 사용했다.
- 연속 대화의 사용자 발언은 같지만 assistant 이력은 해당 모델의 실제 답변이므로 모델별로 달라진다. 고정 assistant 이력을 공유한 통제 실험은 아니다. 이전 답변의 오류 누적도 관찰 대상이다.
- 실험은 .venv의 httpx로 로컬 API에 순차 요청했다. scripts/compare_models.py에 조건과 입력을 보존했다. 자동 채점/추가 평가 모델은 없으며 아래 품질 판단은 사람이 원문을 읽은 탐색 평가다.

짧은 설정:

> 당신은 골목 안의 잘 알려지지 않은 기록 보관소에서 일하는 서린입니다. 신중하고 원칙적인 보관인으로, 비가 내리는 늦은 밤에 장부를 정리하고 있습니다. 접견 공간에서는 잠시 비를 피할 수 있고 안쪽에는 기록 보관용 서가가 있습니다. 한국어로 방문자와 대화하세요.

독립 질문: “안녕하세요.” / “이 늦은 시간에도 일하시네요.” / “여기는 어떤 곳인가요?” / “잠깐 비만 피하고 가도 될까요?” / “저 안쪽에는 뭐가 있나요?”

연속 발언: 쉬러 왔다고 밝힘 → 목록은 괜찮다고 하고 업무 질문 → 앞서 말한 방문 이유 회상 → 이미 읽었다는 주장이 확인된 일인지 질문. 실제 입력·이력은 원문 JSON에 있다.

## 실제 단일 생성 시간

아래는 **API 요청 1회의 wall time**이다. 게임 전체 시간이 아니다. 로딩 영향을 보이기 위해 첫 관측을 분리하고, 첫 응답을 제외한 독립 질문 14개와 연속 4개를 구분했다. 출력 길이/문맥이 달라 순수 연산 속도의 동등 비교도 아니다.

| 모델 | 첫 관측 | 이후 독립 질문 최소 / 중앙 / 최대 | 연속 대화 최소 / 중앙 / 최대 |
| --- | --- | --- | --- |
| 현재 Qwen 4B | 1.37초 | 0.70 / 1.13 / 2.01초 | 1.96 / 2.61 / 2.84초 |
| EXAONE 7.8B | 3.96초 | 0.66 / 1.18 / 1.72초 | 0.96 / 1.49 / 2.04초 |
| Qwen3 14B | 44.32초 | 7.79 / 12.92 / 28.00초 | 10.96 / 14.81 / 18.40초 |

4B 첫 관측은 이미 적재된 상태로 load 약 1.5ms여서 cold-start가 아니다. EXAONE 첫 관측에는 load 약 3.20초, Qwen14에는 약 15.06초가 포함됐다. Qwen14 첫 전체 44.32초 중 나머지는 최초 입력 처리/생성/IO 등을 포함하므로 load만 빼서 고정 추론 시간으로 단정하지 않는다. 이 지연을 허용해도 아래 품질 문제가 남았다.

## 품질 비교 — 원문 근거

| 기준 | 현재 4B | EXAONE 7.8B | Qwen3 14B |
| --- | --- | --- | --- |
| 한국어 자연스러움 | “저는 … 기록들이 있습니다”, “그걸 기억났어요” 등 기본 주어/서술어·표현 오류. 장황한 의미 불명 설명 | 전반적으로 문장 연결은 개선. “비가 많이 오시죠”, “어떻게 도와드릴까요 추가로…” 등 부자연스러움은 남음 | 대체로 문장은 읽히지만 “골목深处” 중국어 혼입, “도움을 드릴 수 있는지 확인해 주시겠어요?”의 화자/요구 혼동, “안쪽에는 기록 보관소입니다” 오류 |

| 설정 유지 | 비에 따라 보관이 안정된다는 새 인과·문서 날짜/내용·지하 서가 등을 창작 | 자료 종류/전설/역사적 중요성·의자/차·다른 방문객 등을 설정 없이 덧붙임 | 비밀/중요 기록·접근 조건·검은 빗물과 서가 묘사 등 미제공 사실을 창작 |
| 없는 행동 생성 | 연속 2턴에 지하 문이 열리기 시작하고 특정 날짜 문서를 봤다고 창작 | 질문만 했는데 “조심스럽게 발걸음을 내려놓으셔서”, “조용히 들어오셔서 감사합니다”로 미제공 행동을 전제 | 독립 질문 3회차 안쪽에서 “젖은 코트를 벗으며 안으로 들어서자”로 사용자 행동을 만들어냄 |
| 짧은 연속 대화 | 방문 이유를 회상하지만 비유/질문을 덧붙이고 주장 확인 기준을 기분·영향으로 바꿈 | 쉬러 온 이유 회상과 미확인 주장 구분은 개선. 목록이 필요 없다는 말 뒤에도 자료 안내를 이어감 | 방문 이유 회상, 주장만으로 확인되지 않았다는 답은 개선. “목록 관심이 있었군요”로 사용자 말을 잘못 되짚고 없는 열람 기록 절차를 덧붙임 |

없는 행동의 제안과 완료 서술은 구분했다. “차를 드릴까요”는 완료가 아니라 미구현 제안/설정 추가이고, “코트를 벗으며 들어서자”는 사용자가 하지 않은 행동을 서술한 문제다. 세 모델 모두 다음 요청 전에 출력 수정 없이 그대로 보존했다.

**EXAONE은 대사 문장 표현의 상대적 개선 후보지만 모든 기준을 통과한 모델은 아니다. Qwen14는 더 느리게 실행해도 14B 크기만으로 충분한 품질 향상이 보장되지 않았다.** 전체 프로토타입 기본 모델을 바꿀 근거로 사용하지 않는다. 표본이 작고 블라인드/복수 평가자/신뢰구간이 없어 일반 모델 성능 순위를 매기지 않는다.

전체 요청·원문·통계: [4B 19개](model-comparison/current-4b.json), [EXAONE 19개](model-comparison/exaone-7.8b.json), [Qwen14 19개](model-comparison/qwen3-14b.json). CSV식 종합 점수로 사람의 주관을 숨기지 않고 위 사례와 원문으로 판단 근거를 남겼다.

## 개선 후보만 기존 구조에 임시 연결한 결과

기본 한국어 문장 표현이 상대적으로 개선된 **EXAONE만** Settings(ollama_model=…)로 기존 앱에 연결해 임시 DB에서 확인했다. 프로덕션 기본값·사용자 서버 환경·플레이 DB를 바꾼 것은 아니다. Qwen14는 추가 게임 연결을 하지 않았다. 새 프롬프트/규칙/라우터/후처리나 추가 검토는 없고 원래 의도→초안→검토 3회다.

동일 5개 질문 1회씩과 공개 경로 3턴, 총 8개 실제 API 요청은 HTTP 200이었다. 전체 wall time은 **첫 요청 7.02초**, 이후 **1.69–2.40초, 중앙값 1.90초**다. 기존 draft_elapsed_ms는 그중 초안만, intent/review_elapsed_ms는 각 단계만 뜻한다. 첫 요청의 초안은 1.00초였지만 의도 단계의 모델 로딩 때문에 전체 7.02초였다. 이 실제 전체 시간을 단일 생성 시간×3으로 추정하지 않았다.

연결 검사는 **현행 어댑터 그대로**라 초안은 temperature/문맥/상한만 명시하고 top_k/top_p는 태그 native 기본값을 사용한다. 앞의 공통 수치 통제 실험과 이 조건이 다르다. 연결 가능성과 실제 처리 시간을 본 것이며 대사 품질의 동일 조건 순위표로 혼합하지 않는다.

결정적인 실패:

- “방문 기록을 선택할게요.” → intent의 action은 select_record였지만 target을 제목 대신 **public**으로 제안했다.
- 기존 서버는 근거 없는 대상을 선택하지 않고 ambiguous_target으로 되물었다. 선택 상태는 바뀌지 않았다.
- 다음 “선택한 기록을 읽어주세요.”도 선택 대상이 없어 되묻기였다. **read_records=[]**, 공개 열람 성공 경로는 완료되지 않았다.

단순 HTTP 성공/JSON 형식 성공을 게임 진행 성공으로 보고하지 않는다. 이 실패를 별칭/금칙어/재시도/추가 검토로 보완하지 않았다. 대사만 EXAONE으로 분리하는 별도 라우팅도 이번에는 구현하지 않았다.

[연결 검사 원본·최종·의도·단계별 시간](model-comparison/exaone-game.json)에 8개를 보존했다. 실제 최종 대사에서도 역사적 중요성을 덧붙이는 등 품질 문제가 남았다. 전체 교체는 보류한다.

## 선택과 보존

- **기본 모델은 기존 4B 유지.** EXAONE은 한국어 대사 연구 후보로 남기고 자동/기본 교체하지 않는다. 14B는 이번 조건에서 교체 대상으로 선택하지 않는다. 두 후보는 다운로드 상태로 남겨 다시 비교할 수 있다.
- 기존 코드·가중치·실패 사례·010 스냅샷은 보존했다. 프로덕션 변경·새 규칙·추가 모델 호출·재생성은 없다. 실험 도구와 보고서만 추가했다. 기존 기능 테스트는 앱 변경이 없어 재실행하지 않았다.
- 기존 생성기가 설정으로 임의 로컬 모델을 받을 수 있음은 임시 연결로 확인했지만, 이 모델이 게임 전체에 적합하다는 뜻은 아니다. 후보를 학습/배포 기본으로 바로 쓰도록 권하지 않는다.
- 학습용으로 30–60초를 허용한다는 기준은 이후에도 유지한다. 이번 미채택의 이유는 속도가 아니라 한국어·설정·행동/의도 안정성의 미해결이다. 더 큰 모델/다른 모델을 고르더라도 같은 원문 비교를 먼저 해야 한다.
