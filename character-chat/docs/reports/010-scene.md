확인일: 2026-10-21 (Asia/Seoul). **코드 동작 변경 + 문서 변경**. [최신 구조](../architecture.md), [010 보존본](../architecture-history/010-scene-knowledge.md), [장면·정보 소유자](../scenario.md), [변경 기록](../changes.md).

## 확인한 불일치와 최소 수정

- archive-2.0은 장소 이름이 “비 오는 밤의 기록 보관소”이고 공개 데이터가 빗물·등불·정원 관리라, 날씨/시설 관리 중심의 장소로 읽힐 여지가 있었다. 첫 인사도 원래 공개 목록을 권했다. 작업 시작 때 사용자가 첫 대사를 이미 “무슨일로 오셨을까요?”로 바꿨으므로 이 방문 목적 질문 방향은 유지했다. 비교 전 상태도 그 사용자 수정본이다.
- 잡담 payload에는 성격 한 줄과 장소만 있어 실제 업무·공간에 관한 사실이 부족했다. 반면 build_context()는 CONFIG 전체를 instructions로 복사했다. **기존 런타임에 플레이어의 숨은 목적이 들어 있던 것은 아니다.** 다만 작가/플레이어용 필드를 CONFIG에 추가하면 그대로 모델에 전달될 잠재 경로였다.
- 일반 공간 질문을 봉인 기록 질문으로 해석하거나 직무 질문을 기록 내용 회상으로 해석한 실제 출력도 확인했다. 그 결과 불필요한 봉인 거절·열람 상태 답변으로 흐를 수 있었다.

새 버전 archive-3.0은 장소/환경/알려진 사실/대화 지침을 분리했다. 작가 기준과 플레이어의 몰래 살펴보려는 목적은 docs/scenario.md에만 두고 코드가 읽지 않는다. 서린은 방문자가 제공하지 않은 목적을 모른다. 실제 비밀·중요 기록의 실존도 확정하지 않았다. 접견 공간에서 비를 피할 수 있음, 안쪽은 보관 서가, 서린은 지금 장부를 정리한다는 최소 장면 사실을 설정했다. 새 이동/잠입/도구/아이템/판정은 없다.

character_instructions()는 캐릭터용 설정 항목만 고른다. 의도 단계는 기존 최소 자료, 잡담은 성격·알려진 사실·대화 지침·관찰된 사건·관계 수치, 검토는 캐릭터용 사실과 서버 결과를 받는다. 사용자 주장과 NPC 추측은 확정 사건과 구분한다. 실제 예문에 따른 코드 분기·답변 하드코딩·새 금칙어·추가 호출·자동 재생성·후처리는 추가하지 않았다. 기존 mock의 고정 예문 대역은 유지하며 새 제목 선택 예문은 동적으로 만든다. 이 대역을 실제 자연어 이해 검증으로 쓰지 않았다.

방문 기록/반출입 장부/보관 분류 안내의 고정 본문으로 임시 공개 데이터를 교체했다. 목록→선택→열람, 봉인 거절/강제 접근 경고·반복 종료/퇴장, 수치, 저장·회귀는 기존 코드다. resolve/server_result/advance_state/apply_turn의 AST가 변경 전과 같음을 확인했다.

## 실제 모델 비교 조건

- 모델 `qwen3:4b-instruct-2507-q4_K_M`, 동일 Ollama 서버. temperature=0.6(초안), 의도/검토=0, num_ctx=8192, num_predict=512, think=false. 설치·모델·시스템 설정은 바꾸지 않았다.
- `python -m scripts.verify_scene before`를 수정 전에 실행했다. 사용자 제시 5개와 추가 표현 5개, 총 10개의 동일 문장을 각기 새 게임에서 전후 비교했다. 새 게임의 설정 자체를 바꾸는 작업이므로 입력 문장·초기 관계는 같고 config는 서로 다르다. 빈 이전 대화에서의 비교이며 장기 대화 검증은 아니다.
- 각 턴은 실제 free API의 의도→초안→기존 검토→저장 흐름이다. 10건 전후 모두 HTTP 200이며 trust/guard/events/progress/ended/memories는 바뀌지 않았다. 확정 사실을 만들지 않는 대화였고 머물기 요청을 새 행동으로 저장하지 않았다.
- raw 초안과 저장된 최종 대사를 모두 보존했다. 비교 도구는 평가용 모델을 추가 호출하지 않고 사람이 아래 원문을 읽었다. 전후 각 입력 한 번씩이며 seed 고정/통계적 유의성 검증은 하지 않았다.
- 첫 수정 후 같은 세트를 한 번 점검했을 때 공간 질문의 sealed 오분류와 불명확한 비 피하기 답변이 남았다. 관련 공간 사실을 명확히 하고 기존 분류/대사 프롬프트의 정보 전달만 보완한 뒤 최종 10개를 다시 실행했다. 개별 응답을 골라 섞지 않았다. 중간 결과는 Git 제외 `.runtime/010-scene-intermediate.json`, 최종 전체 원본은 `.runtime/010-scene-comparison.json`에 있다.

**대사 품질 전체는 부분 통과다.** 장소/공간/비 피하기에 대한 기본 관련성은 개선됐고 모든 대화를 열람 절차로 보내지는 않았다. 숨은 목적을 이미 아는 듯한 반응은 최종 10개에서 없었다. 그러나 처음부터 목적을 입력하지 않았다는 정보 격리 검사와 모델이 모든 상황에서 추측하지 않는다는 보장은 별개다.

“중요한 문서”는 캐릭터 입력에 실제 비밀로 제공하지 않았는데도 모델이 만들어냈다. 따라서 이 응답을 플레이어 목적의 실제 유출이라고 부르지는 않되, 미확인 중요성을 사실처럼 말한 **설정 일치 실패**로 남긴다. 기존 검토도 놓쳤다. 새 검증·재시도·후처리 장치를 붙여 감추지 않았다.

배경 반복과 짧은 인사의 과잉 반응은 해결 완료로 보고하지 않는다. 최종 인사에도 비와 출처 질문이 남았고 늦은 업무 답변도 비를 끌어왔다. 10개 표본의 일부 개선을 일반적인 말투 개선이나 완전한 정보 보호로 확대하지 않는다.

## 자동 기능·정보 경계 검증

- Python **131 passed, 1 warning**(Starlette/httpx), Node DOM 대역 **3종 통과**. UI 구버전 대역에 config가 없는 경우도 안전한 설명 기본값으로 처리했다. 실제 브라우저 레이아웃/VS Code 렌더링 확인은 아니다.
- 기존 128개 상태·잘못된 모델 출력 무저장·설정 보호·회귀 이후 미래 정보 배제·분기 테스트를 유지했다. 활성 테스트/실행 도구의 새 기록 ID·제목은 archive-3.0으로 맞췄다. 역사적 실패 fixture와 과거 보고는 수정하지 않았다. Node 공개 기록 대역에는 구버전 데이터를 남겨 이전 기록 표시도 계속 확인한다.
- 새 3개 검사는 (1) CONFIG에 작가/플레이어/미지의 필드 canary를 넣어 **실제 HTTP payload를 만드는 의도·초안·검토 세 경로** 모두에서 제외, (2) 실제 강제 접근 사건과 관계 수치는 잡담에 전달, (3) archive-2.0 설정/본문/첫 대사/분기의 선택·열람·체크포인트 복원을 새 게임 생성 뒤에도 보존하는 것이다.
- 구버전 fixture는 작업 시작 당시 실제 초기 snapshot을 보존했다. 사용자 첫 인사 수정도 포함하며 자동 마이그레이션하지 않는다. 새 버전은 새 게임에만 적용한다. 기존 분기의 원문은 그대로이며 이후 새 대사 생성 어댑터 자체는 최신 코드다.
- 사용자 작성 `docs/설정.txt`는 읽기만 하고 수정/커밋하지 않는다. domain.py의 사용자 수정은 이번 첫 인사 변경 범위 안에서 방문 목적을 묻는 방향으로 반영했다.

- 공개 기록 목록 요청: 공개 기록 목록을 확인했습니다. 방문 기록, 반출입 장부, 보관 분류 안내가 있습니다. 목록에서 하나를 선택하세요.
- 방문 기록 선택: 방문 기록을 선택했습니다. 아직 열람하지 않았습니다. 열람할 수 있습니다.
- 선택 기록 열람: 방문 기록을 열람했습니다. 두 명의 방문객이 오래된 문서의 보관 여부를 물었고, 당직자는 내용을 기록했지만 문서는 반출되지 않았습니다.
- 열람 전 회귀 뒤 내용 질문: 방문 기록은 아직 열람되지 않았습니다. 내용이 없습니다.

회귀 답변의 “내용이 없습니다”는 현재 열람 맥락이 없다는 뜻인지 기록 자체가 비어 있다는 뜻인지 모호하다. 미래 본문이 입력에 섞이지 않았다는 상태·입력 검사는 통과했으나 표현 품질에는 한계가 있다.

## 남은 범위

이번에는 실제 비밀·추가 퍼즐/퀘스트·잠입·새 도구/아이템·이미지·신뢰/경계 계산을 추가하지 않았다. 새 금칙어 목록·추가 모델 호출·재생성·후처리도 없다. 기존 검토 모델의 오탐/누락과 장기 잡담 반복은 남아 있다. 다음 개선은 실제 플레이의 잘못된 추론/어색한 표현을 사례로 보존해 다루며, 이번 결과를 전면적인 대화 품질 해결로 보지 않는다.
