# 008 · 열람 후 내용 질문의 회상 실패 수정과 실제 검토

확인일: 2026-10-21 (Asia/Seoul). [사용자 실패 발췌](../../tests/fixtures/record-recall-missed.json)는 선택만 했을 때와 실제 열람 후 모두 첫 인사로 답한 사례다. 선택·열람의 조작 차이만으로 설명할 수 없었으며, 007에서 열람 직후의 내용 질문을 시험하지 않은 빈틈이 있었다.

## 확인한 입력 문제와 변경

- speak도 “이번 서버 결과와 다음 진행을 전달”하는 과제로 전달해 내부 접수 문장·메뉴 안내와 실제 질문 응답을 혼합했다.
- speak의 “발언을 전달했습니다”를 과거 assistant 대사로 다시 넣었다. 중간 실제 시험에서는 모델이 이 접수 문장을 그대로 답변했다. 초기 인사도 반복 예시로 남아 있었다. 이 입력 경로를 확인했으며 모델 내부 반복의 단일 원인을 증명한 것은 아니다.
- 읽은 본문은 과거 열람 결과에 있었지만 최근 열람과 현재 선택을 별도 근거로 제공하지 않았다. read_records는 중복 없는 ID 목록이므로 이것의 마지막 항목이 최근 열람이라는 가정도 맞지 않는다.

`reading_context()`는 현재 스냅샷의 기록 데이터·열람 ID·record_read 사건 순서로 선택 상태와 최근 열람 본문을 계산한다. 모델이나 사용자 주장으로 읽음 처리를 만들지 않는다. 기록을 다시 읽거나 다른 기록을 선택해도 실제 최근 열람을 찾는다. 별도 DB·지속 기억은 추가하지 않는다.

`confirmed_history()`는 사용자 발언·행동과 server 역할의 확정 사건을 전달한다. 발언 접수 문구·첫 인사는 모델용 이력에서 제외한다. 결과 없는 구버전 캐릭터 대사는 unverified_character로 구분한다. 표시용 원본 대사·스냅샷은 그대로 보존한다.

speak는 확인된 열람 근거와 현재 질문을 마지막 user 작업으로 전달한다. 이 때 내부 “발언 접수됨”을 전달할 대사로 요구하지 않는다. 선택식 행동은 기존의 서버 결과 전달 과제를 유지한다. speak 서버 카드의 다음 진행도 실제 목록·선택·열람 상태에 따라 표시하고 미지원 허가 절차를 매번 반복하지 않는다. 금지어·유사도 차단·재생성·모델 교체·자유문장 행동 해석은 추가하지 않았다.

## 변경 전 비교와 중간 실패

같은 질문·같은 세 상태의 기존 코드 비교에서 열람 후에도 다음처럼 답했다.

> 비가 오는 밤, 기록 보관소는 여전히 정돈된 상태입니다. 공개 기록을 선택하고 열람할 수 있습니다. 다음으로는 목록을 다시 확인하거나 기록을 선택해 보시겠어요?

초기 변경은 열람 후 본문을 답하기도 했지만 선택·회귀 상태에서 질문을 그대로 복사했다. 질문 작업을 분리한 뒤에도, 내부 접수 문장을 이력에 남긴 조건에서는 그 문장을 답하는 실패가 있었고 한 긴 사례는 중복 본문 때문에 문맥 예산 502로 끝났다. 이를 성공으로 세지 않았다. 마지막 변경은 접수 문구와 실제 사건을 분리하고 본문 중복을 줄였다. 이력을 길이 때문에 몰래 잘라 내거나 예산을 올리는 변경은 하지 않았다.

## 최종 자동 검증과 실제 대사 검토 구분

**자동:** Python 82개 통과, deprecation 경고 1개. 3개 기록의 선택·열람·회귀 근거, 최근 열람 사건 순서, 현재 선택과 최근 열람의 구분, 발언의 상태 불변, 허위 읽음 주장 무효, 내부 접수 문구 미재사용을 추가했다. 기존 저장 원자성·모델 오류·설정 보호·회귀 검증은 유지한다. Node DOM 대역 2종도 통과했으며 실제 사용자 브라우저 렌더링을 확인한 것은 아니다.

**실제 질문:** `.venv/bin/python -m scripts.verify_record_recall`로 11개 질문 응답을 확인했다. 선택식 행동 준비는 MockProvider, 질문 응답은 모두 실제 `qwen3:4b-instruct-2507-q4_K_M`이다. 임시 SQLite의 실제 회귀 API를 사용했고 플레이 DB는 사용하지 않았다. 자동으로 상태·근거 격리를 검사하고, 아래 대사 의미는 사람이 별도로 읽고 평가했다.

핵심 질문 기준은 11개 모두 충족했다. 3개 기록 각각 선택·회귀 때 미열람을 말하고 열람 후 본문을 답했다. 다른 기록을 선택해 둬도 최근에 읽은 기록으로 답했다. 다만 “방금 읽은 기록은 아직 열람되지 않았다”처럼 전제를 고치는 한국어가 어색하고, 불필요하게 절차를 덧붙이는 경우는 남았다. 모든 대화 품질이 해결됐다는 뜻은 아니다.

질문 응답 시간 0.74–1.28초, 중앙값 0.84초. Git 제외 원본 요청·출력·진단: `.runtime/008-record-recall.json`.

## 기존 경로 재검증

별도로 `.venv/bin/python -m scripts.verify_ollama`를 실행해 기존 11사례의 상태·저장·회귀 검증을 통과했다. 실제 모델이 목록·선택·열람을 안내하고 강제 접근 재시도에 완료된 면담 종료를 알렸다. 신분증 검증·허가 발급을 실제로 완료했다고 주장하지 않았다.

이 기존 경로의 대사 품질은 여전히 부분 통과다. 회귀 후 “열람하지 않았다”와 “확인할 수 없다”를 함께 말하거나, 신분증 미지원 설명이 공개 열람 제한처럼 들리는 등 표현 문제가 남았다. 이는 회상 질문 11건의 핵심 기준 통과와 구분한다. 전체 자연어 진실성 자동 판정기는 없다.

기존 경로 응답 시간 0.70–1.27초, 중앙값 0.95초. GPU 적재는 `/api/ps`의 size=size_vram=3,877,571,133 bytes, context=8192로 확인했다. 모델·시스템 설정·의존성은 바꾸지 않았다.

## 직접 확인

기존 archive-2.0 게임의 저장된 열람 사건을 그대로 사용하므로 새 게임은 필수가 아니다. 서버가 --reload로 실행 중이면 코드 반영 후 같은 질문을 다시 보낼 수 있다. --reload가 아니면 게임 서버만 재시작한다. 이미 저장된 잘못된 대사를 수정하거나 삭제하지 않는다.

1. 목록·선택까지만 한 상태에서 “방금 읽은 기록은 무슨 내용이었죠?” → 아직 읽지 않았다고 답해야 한다.
2. 공개 기록 열람 후 같은 질문 → 실제 본문에 근거해 답해야 한다.
3. 열람 전의 선택 지점으로 회귀 후 같은 질문 → 미래 본문을 답하지 않아야 한다.
