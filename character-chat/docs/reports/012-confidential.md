# 012 · 기밀 제목·출처 확인과 관계 조정 설정

2026-10-21 (Asia/Seoul). 코드 동작 변경. EXAONE 기본 모델·기존 게임·mock 유지. 외부 API/추가 모델/시스템 설정 변경 없음.

## 구현과 완료 범위

새 게임 archive-4.0부터 서버의 confidential-1 정의에 ‘계몽의 서’의 실존, 서린의 존재/위치 지식과 개요 수준 지식만 둔다. 구체 위치·개요 문장·본문·제목을 알아내는 경로·잠입은 만들지 않았다. 실제 제목을 감지하는 것은 서버이며 지원 문자열은 계몽의 서/계몽의서뿐이다. 부정/인용도 이름을 말한 사실은 감지하지만 읽음/접근/내용 지식/범죄/허가로 승격하지 않는다.

미등장 제목·서린의 비공개 지식은 모델 입력에 넣지 않는다. CONFIG에는 confidential_policy_version만 저장하고, DEFINITIONS는 모델에 복사하지 않는다. 제목 언급 후에도 공개 경계·확인 질문·미검증 주장만 전달한다. source_check의 직전 질문은 화면에도 나온 서버 질문이다. 숨은 목적은 기존처럼 docs/scenario.md에만 있다.

상태: confidential에 title_mentioned/first_mention_turn/disclosed_by_serin/source_status/rechecks/additional_guard_applied/source_claims/last_question/closing_reason을 저장한다. 관계 설정 전체와 버전, 적용 횟수도 같은 JSON 스냅샷에 저장한다. 기존 SQLite 테이블/열은 그대로다.

초기값·반복 정책·임계치·합산은 [관계 설정 설명표](../relationship-rules.md)를 따른다. 최초 +10, 거절/명백한 재확인 후 회피 +5, 신뢰 0을 잠정 사용했다. 반복 제목은 확인 횟수나 경계를 더하지 않고 짧은 확인 응답만 요청한다. 구체적 출처는 user_claim/verified=false로 저장한다. 첫 모호함/화제 전환은 수치 없이 한 번 재확인, 다음에도 모호하거나 uncertain이면 감점 없이 닫는다. 출처 질문을 종료한 뒤 일반 대화는 계속 감점하지 않는다.

자유 입력의 **기존 의도 호출**에 SourceAnswer(type/evidence)를 추가했다. 서버가 유형/현재 질문 단계/근거를 보고 상태를 정한다. source_answer.evidence는 스키마 const로 현재 입력 전체 원문만 허용하고 서버에서도 확인한다. 이는 생성 후 잘못된 문자열을 고치는 치환이 아니다. 처음 제목을 말한 턴은 아직 직전 질문이 없어 출처 답변까지 판정하지 않는다. direct는 해석 호출을 늘리지 않고, 출처 답변이 없으면 질문 상태 유지. 자유 입력 3회/직접 행동 2회 그대로다.

특수한 문체 금칙어·추가 검토·재생성·새 문자열 후처리 없음. 기존 검토 입력에는 이번 기밀 경계/응답 과제를 전달하고, 불필요한 상태/지침 중복을 줄였다. 기존 검토 거절과 종료/되묻기 등의 서버 대체 처리는 유지한다. 개발 패널에 규칙·근거·전후·합계·실제 차이·최종값과 무저장 여부를 표시한다.

## 실제 연속 게임: 18턴, 전체 목표는 부분 통과

8개 기능 묶음 중 7개가 기대와 일치, 전체 integration_passed=false다. **재확인 후 회피 +5 경로는 최종 모델의 오분류로 실패**했다. 자동 상태 테스트의 해당 전이 통과와 구분한다.

- 인사/중요한 기록 질문은 경계20 유지, 실제 제목 입력 전 요청에 기밀 이름 없음.
- “계몽의 서는 모르는데요.”는 경계30·질문 pending, 강제 접근0. 실제 대사 “그 이름을 어디서 처음 접하셨는지 좀 더 자세히 말씀해 주실 수 있을까요? 이해를 돕기 위해 출처나 맥락을 알고 싶습니다.”
- 한 씨에게 들었다는 설명은 미검증 주장으로 저장, 신뢰30/경계30·closed. “출처 설명을 들었습니다. 추가 정보가 필요하시다면 언제든 말씀해 주세요.”
- 최초 언급 전으로 회귀하면 상태 정확히 동일, 원본 보존, 의도/대사/검토 입력에 이름과 한 씨 출처가 없음. 새 분기 재언급 +10.
- 제목 반복은 +0·재확인 횟수0 유지. 첫 모호함은 +0·재확인1. 이후 회피 입력을 topic_change로 잘못 봐 **경계30 그대로 closed**. 다음 일반 대화도30 유지. 기대값35가 아니므로 실패다.
- 명시적 거절은 경계35·closed. 이 규칙만으로 종료하지 않음.
- direct 강제 접근+최초 제목은 신뢰15/경계55, 다음 direct 강제 접근은 경계80·기존 종료. 직접 행동은 출처 분류를 하지 않으므로 거절 +5는 이 경로에 없다.
- 공개 목록→방문 기록 선택→열람 성공, 관계20 유지.

최종 18턴 중 기존 서버 대체는 3턴(review_rejected 1, clarification_required 1, branch_ended 1)이며 모델 대사 품질 통과로 계산하지 않는다. 첫 강제 접근을 포함한 복합 입력에서 초안이 경고 설명을 생략하기도 했지만 서버 카드/수치/종료 규칙은 유지됐다. 배경·후속 질문 반복, 메타 표현, 질문 종료 후 불필요한 “추가 정보” 제안도 남았다. 소장 여부/구체 위치/허가 발급을 새 상태로 확정하지 않았다. 표면적인 문체를 고치기 위한 장치는 추가하지 않았다.

최종 free 16턴의 기존 3단계 응답은 약 **1.54–3.04초, 중앙값1.96초**. 직접 행동2턴은 별도 2호출이다. 샘플링은 기존 의도/검토 temperature0, 초안0.6, ctx8192/predict512/think=false다.

## 중간 실패와 실행

1차: 출처 evidence에 설명을 생성해 서버가 claim을 저장하지 않음. 이름을 부정하는 첫 대사도 출처 질문을 놓침.
2차: 근거 const/응답 과제 전달 후 첫 질문은 개선됐지만 구체적 출처 턴 검토 입력이 기존 바이트 예산을 초과해 턴 무저장.
3차: 필요한 검토 입력을 선별한 뒤 연속 18턴 통과. 그러나 세부 분류 오판/대사 품질은 남음.
4차: 유형 의미 설명을 조정했으나 구체적 출처를 vague로 오판해 실패.
5차: 입력 원문을 분기 자료와 분리한 뒤 구체 출처는 개선됐지만 회피를 topic_change로 봐 실패.
6차: 프로덕션을 더 고치지 않고 같은 조건에서 전체 경로를 끝까지 기록. 실패를 통과로 바꾸지 않았다. 런타임 재생성/자동 재시도는 어느 단계에도 없다.

```bash
# 프로젝트에서 로컬 Ollama 서버를 켠 뒤 별도 결과 파일로 재실행
.venv/bin/python -m scripts.verify_sources --output .runtime/012-source-my-run.json
```

기존 결과가 있으면 중단한다. 임시 DB만 사용하고 실패/전체 판정도 JSON에 남긴다. 명령의 정상 종료를 모든 모델 품질 통과로 간주하지 말고 checks와 classification_matches를 확인한다. [현재 구조](../architecture.md), [012 스냅샷](../architecture-history/012-confidential-relationship.md), [변경 기록](../changes.md).
